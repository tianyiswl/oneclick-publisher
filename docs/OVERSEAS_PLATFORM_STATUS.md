# 海外平台接入状态

## 统一执行原则

TikTok、Instagram Reels 和 Facebook Reels 继续使用一键发自己的本地浏览器
会话。YouTube 改用 Google 官方桌面 OAuth：用户在系统默认浏览器授权，刷新令牌
只进入 macOS Keychain 或 Windows Credential Locker，SQLite 只保存不含令牌的引用
和频道 ID。YouTube 因此需要 Google Cloud 桌面 OAuth 客户端 ID，但不需要用户逐个
申请开发者应用。

本分支已经完成 YouTube 登录、账号保存和客户端重启检测的本地接线；其中共享界面
和账户服务改动仍须集成线审查，尚未进入正式客户端。YouTube OAuth 账号在官方发布
路由接通前不会出现在发布中心，当前也没有配置真实 Google 项目或执行真实授权。

| 平台 | 账号登录与检测 | 视频预检 | 正式动作 | 当前边界 |
| --- | --- | --- | --- | --- |
| TikTok | 可见登录、自动保存、静默检测 | 上传并填写文案，停在 Post 前 | 用户确认后可见浏览器立即发布 | 强制公开；定时、AI 声明和自定义封面暂不开放 |
| YouTube | 系统浏览器 OAuth、Keychain/Credential Locker 保存、重启后同频道检测；仅本地测试通过 | 官方 API 零写入本地预检已实现，尚未接发布中心 | 未开放 | 共享接线待集成审查；无真实 Google 项目、账号或上传证据 |
| Instagram Reels | 与 Facebook 共用 Meta 会话 | 选择 Instagram 目标并填写 Reels | 可见浏览器二次确认后执行 | 验证码、双重验证、风控或未知提示会停止 |
| Facebook Reels | 与 Instagram 共用 Meta 会话 | 选择 Facebook 目标并填写 Reels | 可见浏览器二次确认后执行 | 只有明确平台回执才记为成功 |

## 客户端入口

- TikTok 和 Meta 的“绑定账号”在一键发独立浏览器会话中打开平台官网。
- YouTube 的“绑定账号”在系统默认浏览器打开 Google 官方授权页，授权完成后自动保存频道身份和系统凭据引用；不提供手动保存 Cookie 的回退按钮。
- “检测登录”默认静默，只检查已保存会话；异常时提示用户手动重新登录，不自动弹出登录页。
- Instagram 与 Facebook 共用一次 Meta 登录，但在账号列表和发布目标中分别显示。
- YouTube OAuth 账号会显示在账号管理，但不会进入现有浏览器发布账号列表；其他平台行为不变。
- 账号数据库不保存 YouTube 刷新令牌或访问令牌，只保存平台、主体、显示名、系统凭据引用、频道 ID 与检测状态。

## 当前发布门槛

1. 海外恢复流程当前只验收视频，图文和纯文字不会创建伪任务。
2. TikTok 与 YouTube 首版只开放单账号、单视频、立即发布；正式动作必须保持浏览器可见。
3. Instagram/Facebook 正式发布必须保持浏览器可见，并完成两项一次性确认。
4. 无法稳定回读的选项会在上传前阻断，不会静默忽略。例如 TikTok 非公开可见、AI 声明、自定义封面，YouTube 关闭订阅者通知，以及 Meta AI 声明。
5. 只有平台返回明确发布或定时成功证据，对应执行项才会记为成功。

## 2026-08-23 YouTube 本地收紧

- 预检现在只接受一个账号和一条视频，并要求上传器返回视频、标题、受众、可见性，以及用户实际填写的正文、标签、封面、播放列表或 AI 声明等逐字段证据。缺一项就停止，不再把“没有抛异常”记成预检成功。
- [YouTube 官方上传说明](https://support.google.com/youtube/answer/57407?co=GENIE.Platform%3DDesktop&hl=zh-CN)指出，上传流程未完成时关闭窗口，视频会以私密状态保留在 Studio 的 Content 页。因此 YouTube 预检会明确返回 `private_upload`，不再声称“没有保存任何平台内容”；它仍没有点击最终 SAVE/Publish，也不代表公开发布。
- 正式动作后的上传弹窗关闭不再单独算成功。现在只接受明确平台成功提示，或 Content 页中出现本次新增、标题和可见性都匹配的视频条目。
- 私密或不公开结果只记为已保存，不记为已公开发布。验证码、两步验证或 Google 安全挑战出现时，本次自动流程立即停止，不会在人工处理后自动续点最终按钮。
- 上述改动目前只有离线自动测试证据；尚未使用专用 YouTube 账号完成首次登录、客户端重启检测、真实预检或 Content 页回读，也没有执行任何最终保存或发布动作。

## 2026-08-23 YouTube 官方 OAuth/API 适配器边界

- Google OAuth 和 YouTube 私密上传适配器已经在本地实现，并只用假 HTTP 响应完成离线测试。2026-08-27 又完成了系统浏览器登录、账号持久化、操作系统凭据库和重启检测的分支接线；共享接线提交仍待集成线审查，因此正式客户端当前仍不能通过这套适配器完成授权。私密上传适配器仍未接入共享发布路由。
- 产品分支没有配置 Google Cloud 项目或 OAuth 客户端。没有进行真实系统浏览器授权、频道身份读取、客户端重启后的登录检测、私密上传、处理完成回执或公开视频结果验证。
- 本地预检是零写入；私密上传适配器必须取得当前明确确认才会开始。结果核验只读取本次上传返回的精确视频 ID，并且只接受频道、标题和私密可见性都匹配的结果；回读歧义或不匹配就停止。遇到失败或结果不明也不会自动降级到浏览器路线、自动重试或继续上传。这些行为目前都只有离线测试证据，不表示真实上传已经成功。
- Chrome for Testing 的既有浏览器路线仍被 Google 以“此浏览器或应用可能不安全”拒绝，相关真实登录失败证据保留在本页下一节。这是不再重试该浏览器登录路线、改为接入 Google 官方 OAuth 的依据；新路线虽然已完成分支接线，仍不等于已取得 Google 或 YouTube 的真实验证。
- 本节只说明 YouTube 的本地代码边界，不表示 TikTok、Instagram Reels 或 Facebook Reels 新增了 OAuth、官方接口或发布能力。

## 2026-08-27 YouTube 桌面登录接线

- “绑定账号”已在本分支改为创建 Google 官方桌面 OAuth 会话，并使用系统默认浏览器、127.0.0.1 随机端口回调、一次性 state 与 PKCE。Google 项目客户端 ID 缺失、用户拒绝、回调不匹配或频道不唯一时都会在写入账号前停止。
- 刷新令牌通过 `keyring` 进入 macOS Keychain 或 Windows Credential Locker。数据库只保存 `youtube-oauth:` 不透明引用和公开频道 ID；保存数据库失败时会撤销刚写入的系统凭据。
- 客户端重启后的静默检测会从系统凭据库刷新访问令牌，再调用 `channels.list(mine=true)`，只有读到与数据库完全相同的唯一频道 ID 才记为正常。重新登录若返回另一个频道，也不会覆盖原账号。
- OAuth 账号目前只在账号管理显示，“打开后台”和浏览器会话头像刷新不可用；发布中心继续只读取浏览器会话账号，防止尚未接通的 OAuth 上传路线被误用。
- 本地证据为 93 条 YouTube 相关测试和合并当前主线后的 2167 条全量测试通过。测试全部使用假浏览器、假 HTTP、假系统凭据库和临时 SQLite，没有访问 Google，也没有创建、上传或发布视频。
- 共享接线提交是 `b08a29b`，范围检查按规则返回 `REVIEW_REQUIRED`；它不能由海外分支自行合并。真实 Google 授权必须等集成审查、Google 测试项目和桌面 OAuth 客户端 ID 都准备好后再执行。

## 2026-08-23 YouTube 首次真实登录结果

- 在本分支源码客户端选择 YouTube 绑定账号后，客户端实际启动的是 Playwright 管理的 Chrome for Testing。
- 用户在 Google 官方登录页输入账号标识后，Google 明确返回“此浏览器或应用可能不安全”，拒绝继续登录。这证明当前浏览器登录路线本身被平台拦截，不是本地账号文件缺失、验证码未填或密码错误。
- 本次随后在客户端点击“取消登录”；客户端回读“登录已取消，未修改账号会话”，账号列表仍为 0。没有保存 Cookie 或 storage state，没有上传视频，也没有触发 SAVE/Publish。
- 因首次登录未通过，客户端重启后的静默检测、真实单视频预检和 Content 页回读都没有执行。继续重复打开同一种测试浏览器没有验证价值，也不应通过隐藏自动化特征、复制普通浏览器 Cookie 等方式绕过 Google 安全限制。
- 下一步是由集成线审查并接入 `b08a29b` 的共享登录改动；随后配置 Google 测试项目和桌面 OAuth 客户端 ID，再经大帅单次授权执行真实系统浏览器授权与重启同频道检测。发布路由、私密上传和精确 `video ID` 回读属于后续独立阶段，不能由登录通过推定为可用。

## 尚未完成的真实验收

当前版本完成了源码接入、界面门控、正式发布回执契约和离线回归，尚未使用真实海外
账号与测试视频执行平台验收。下一步需要在一键发中逐个平台绑定专用测试账号，再验证
身份、字段、素材、最终按钮、验证挑战以及平台内容列表回执。

YouTube 的新静默检测会用系统凭据库中的刷新令牌调用官方频道接口，并要求读回同一频道 ID；
它还没有用专用测试账号证明客户端重启后仍能识别同一频道身份，也没有当前真实账号的上传
权限回读。这两项仍属于真实验收缺口，不能由离线测试替代。

## 安全边界

- 二维码、Cookie、storage state、OAuth 授权码和令牌不写入代码仓库、安装包、发布包或长期日志。
- 登录失效、验证码、二次验证、风控和未知合规提示都是安全停止条件。
- 平台动作失败或回执不明确时不会自动盲目重试，避免重复发布。
