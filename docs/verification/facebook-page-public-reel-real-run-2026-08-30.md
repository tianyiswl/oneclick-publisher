## 任务 91 暴露并修复的回读缺陷

1. Meta 当前内容表会先渲染表头，再延迟渲染数据行。旧实现连续两次看到空签名就接受空列表，可能在 Reel 出现前提前结束。现在只有观察到至少一条已解析的数据行，才允许以稳定表格结束；只有照片时仍能明确形成空 Reel 基线。
2. Meta 还可能先短暂显示“暂无内容”，随后才渲染已有内容。现在只有唯一明确空状态连续稳定出现、且期间始终没有数据行时才接受真正空列表；临时空状态后延迟出现 Reel 的回归已覆盖。
3. “刚刚”“1 分钟前”等相对时间原来会在每次采样时重新取当前秒数，导致同一行的签名漂移。现在一次列表读取共用固定观测时刻，并统一到整分钟。
4. Meta 列表时间只精确到分钟。旧实现把 `22:24` 解析为 `22:24:00`，再与 `22:24:02.710` 的点击时间直接比较，导致同一分钟的新 Reel 被误判为点击前内容。现在只在平台时间恰为整分钟且与点击同一分钟时接受；带真实秒数的点击前内容仍被拒绝，claim 写入前的二次校验也使用同一合同。
5. 只读核对结果为 `none/mismatch` 时，旧实现会残留 `facebook-reconcile-*` worker token。现在使用 exact token 的原子条件更新只清理自己的 token、PID 和心跳，同时保留 `ambiguous / blocksReplay=1`；并发替代 owner 不会被误清。
