# 内容项目调用一键发的稳定交接合同

## 主通道

五个内容项目不再通过辅助功能点击一键发桌面控件。安装版客户端以
`--mcp-server` 启动本机 stdio MCP，Codex 只传入：

- 结构化内容包 `manifest` 绝对路径；
- 项目标识；
- 各平台的定时发布时间（可选）；
- 预检 taskId 和当次一次性授权（仅正式发布）。

项目标识通过本机 `publish-profiles.json` 解析成明确的平台和账号 ID。
这个文件不保存 Cookie、密码、验证码或账号会话路径。

## 安全边界

- 内容项目默认只能调用预检工具。
- 正式提交必须绑定全部成功的预检，并消费短期、一次性本地授权。
- MCP 不接受也不返回 Cookie、密码、验证码或 CAPTCHA。
- MCP 启动现有受控 CLI 子进程执行任务。如平台触发验证，仍由一键发本机原生窗口处理，验证内容不经过 MCP。
- Codex 只通过 taskId 轮询阶段、平台状态、错误和回执。

## 平台后台变化时的边界

只要 `oneclick-content/v1` 内容包合同没有改变，平台官方后台的按钮、选择器、
分页或回执变化，都只修改一键发对应平台执行器。五个内容项目不需要跟着修改交接。

如果未来内容包合同必须升级，一键发必须提供明确迁移或返回固定错误码，
不允许静默忽略字段、污染正文或让五个项目各自猜测新格式。

## 硅基进化公众号草稿桥

该通道是硅基进化 V1.2 冻结内容包的兼容入口，只保存公众号草稿，
不发表、不群发、不定时发表。它暂时保留，但不是五个内容项目的日常主通道。
等通用公众号只存草稿工具经过真实平台验收后，再删除这个专用兼容桥。

## 一次性注册

Codex 只需在本机全局配置一次一键发 MCP，不需要在每个内容项目重复改交接文件。
安装版命令为：

```toml
[mcp_servers.yijianfa]
command = "/Applications/一键发.app/Contents/MacOS/一键发"
args = ["--mcp-server"]
startup_timeout_sec = 30
```

Windows 只需把 `command` 换成实际 `YiJianFa.exe` 绝对路径，`args` 保持不变。
