# 抖音带货批量工作流

“抖音带货”是独立于多平台发布中心的本地团购视频工作台。首版面向同一抖音账号一次处理 1 至 20 条视频：共享标题、文案、标签、收藏音乐和作品内容声明；每条视频分别指定官方地点与发布时间。

## 用户流程

1. **内容准备**：选择一个状态正常的抖音账号、1 至 20 条本地视频，填写共享标题、文案和标签。内容可只保存在本机，恢复不会创建平台草稿。
2. **平台设置**：选择已同步到本机、且来自该账号“收藏”列表的音乐；选择一项作品内容声明；为每条视频选择完整地址可见的官方地点预设。默认立即发布；也可设定 Asia/Shanghai 的起始时间和间隔，并对单条时间覆盖。
3. **检查与提交**：先逐条进行预检并回读编辑页字段。用户在总确认页检查每条视频、完整地点和发布方式后，才能提交批量发布。

地点预设仅是本机保存的“下次可复用选择”。每一次预检或提交仍会在当前抖音编辑页按范围（国内或本地）重新搜索，并要求名称、完整地址和平台可读标识精确匹配；预设绝不替代真实平台回读。

## 地点候选分页与本地缓存

地点搜索按受控账号、范围、关键词和返佣筛选隔离缓存。首次展示优先从本地缓存取 10 条；用户点击“加载更多地点”时，只要同一查询的本地缓存尚未读完，就继续按每页 10 条在本地分页，不访问平台。仅当本地缓存已耗尽后，后续每次手动加载才会请求当前平台候选面板的下一批，并将经校验的新候选追加到当前结果和本地缓存。

正式发布不依赖用户可见的重新检查操作。当当前页的候选仍无法完整匹配所选 POI 身份时，执行链在共享总等待期限内自动续页，一次最多执行 10 次加载、查看 100 条受控候选；达到次数、候选数或时间上限即安全停止，不降级为模糊匹配。地点身份不一致、候选歧义或全部分页穷尽仍未找到时，只将该地点标记为待校对；下次查询会在后台无感重新向平台校对，不要求用户点击可见的“重新检查平台”按钮。

缓存命中只能证明本机曾保存过已校验的候选，不等于当前编辑页已写入地点，更不等于平台草稿、定时或公开发布成功。正式发布仍必须完成名称、完整地址、平台标识和返佣类型的全 POI 身份匹配，严格回读选中态，并取得最终平台回执。

## 检查与提交后返回修改

全部视频都已成功的任务，不提供返回修改；如需继续创作，请新建内容。只有任务已经结束，且存在明确失败的视频，或用户曾主动暂停而留下未开始的视频时，才可以返回修改。

返回修改只在本机创建一个可编辑副本，只复制失败或未开始的视频。已经成功的视频会锁定，平台状态无法确认、正在执行、登录或验证中的视频也不会被复制。原任务及其中的视频状态、平台回执和失败记录保持不变；新的修改任务会在任务明细中标明来源任务。

返回修改不等于“继续发布”：此时不会访问账号、启动浏览器、上传视频、保存平台草稿或提交发布，也不会立即创建新任务。用户完成修改并在“检查与提交”再次确认后，才会创建新的任务。

返回前，客户端必须确认相关采集和编辑会话已经完全关闭。只要关闭状态无法确认，就不会返回修改，以免与仍在运行的操作冲突。

## 平台设置隔离采集

进入平台设置时，客户端为本次操作创建唯一代际。国内地点采集器随代际启动；收藏音乐采集器只在用户点击刷新时启动；本地点采集器只在首次本地搜索时启动。三者各自使用独立的浏览器上下文、页面和临时 Session；动作由单队列串行，国内与本地范围不在同一采集页往返切换。地点搜索自身可直接启动，不依赖刷新音乐或所谓音乐预热。

采集页只返回本机候选。选中音乐、地点或声明时，客户端仅记录“本地已选，发布时重新核验”；它不等于已写入正式编辑页，也不是草稿、定时或公开发布回执。单个采集器失败时只重建该采集器，不替换其他两个实例；代际或实例不匹配的迟到结果必须丢弃。

正常继续、途中放弃、登录失效、账号或内容变化、发布完成与客户端退出都走同一个 `cancel-and-close` 屏障。保存预检或启动正式发布前，必须同时取得 `closed=true` 且 `aliveCollectorCount=0`；否则安全停止。放弃后清空当前批次的音乐、地点、范围、声明和排期选择，但保留账号、视频、标题、文案和标签。

`tools/verify_douyin_commerce_collectors.py` 是开发者验证器。默认只打印 A/B/C 三个代际的计划，不读取账号、不启动浏览器；显式 `--execute` 只允许使用内置探针读取候选，三个代际依次覆盖“音乐→国内→本地”、“国内→音乐→本地”和“本地→国内→音乐”，国内搜索次数分别为 20、20 和 1，且每个代际都必须关闭。报告只保存公开诊断、实例 ID 短哈希、候选数和关闭结果；`finalSubmitCount`、`draftSaveCount` 和 `publicPublishCount` 永远为 0。遇到登录、账号验证、频控或服务降级必须立即关闭当前代际并停止后续序列。运行 `--execute` 仍必须获得 Andy 对本次实机验证的单独明确授权，不能从计划通过或旧授权推断。

## 执行顺序与状态

批量执行器每次只处理一条视频，固定顺序为：

`上传并回读标题/文案/标签 → prepare_publish_settings 取得干净平台设置基线 → 选择收藏音乐 → 选择声明 → 搜索并写入地点 → 写入发布方式/排期 → 预检回读 →（仅已确认发布）最终提交 → 平台管理页回读`。

- 预检始终以 `runtimeMode=preflight` 与 `debugDryRun=true` 执行，绝不会调用最终提交。
- 正式提交必须同时具备 `runtimeMode=publish`、`debugDryRun=false` 和 `batchConfirmed=true`。缺少其中任一项时不创建提交线程。
- 立即发布只有收到平台最终发布回执才标为成功；定时发布还必须从管理页回读标题和指定的 Asia/Shanghai 时间才标为已定时。
- 单条出现可诊断的字段或平台失败时，记录该条失败并继续下一条；二维码、验证码、登录失效、未知合规/风控或控件无法唯一确认时，整批暂停，等待用户处理后从当前会话继续。
- 短信验证码由一键发原生对话框承接。验证码仅在内存中处理；重发受平台最短 60 秒间隔限制，不保存到任务、日志或内容包。

## 载荷与任务记录

批次信封使用：

```text
workflow=douyin-commerce-batch
commerceMode=local-group-buy
```

每条内部操作载荷使用旧单视频的 `workflow=douyin-commerce`，并带 `batchWorkflow=douyin-commerce-batch`。这是执行器内部契约：通用发布服务和旧单视频执行器都会拒绝此类内部条目，不能将逐视频任务误写成一次通用平台成功。

任务记录逐条保存视频名称、完整地点、立即发布或北京时间定时、编辑页预检结果及最终平台回执。不会保存 Cookie、二维码、短信验证码、账号凭据、页面 HTML、原始请求或门店/商品库。

## 明确不支持的范围

- 图文、文字、多账号、跨平台批量；
- 门店绑定、商品/套餐选择和商品库管理；
- 官方 API、签名参数、私有接口或第三方地图数据；
- 自动选择第一首音乐、模糊匹配地点、跳过验证码或把预检当作发布成功。

## 实机验收门槛

以下清单把离线验证、真实平台预检与用户授权后的真实提交明确分开。离线测试或编辑页字段回读都不能证明内容已经在平台发布。

### 一、离线与客户端验收（不启动平台浏览器）

1. 运行批次草稿、地点预设、排期、任务回执、串行执行器、单视频发布与验证码链路的离线测试；确认 1 至 20 条限制、共享字段、单条地点、立即发布/定时间隔/单条覆盖、暂停恢复和平台回执门槛都已覆盖。
2. 启动客户端 UI 自检，确认“抖音带货”入口、批次内容保存/恢复、地点预设、逐条时间、总确认页与任务记录的批量场景标识可见。
3. 此阶段不读取账号会话、不上传视频、不创建草稿、不调用最终提交；通过结果仅代表本地实现可用。

建议命令：

```bash
.venv/bin/python -m unittest -v \
  test_douyin_commerce_batch_draft_service \
  test_douyin_location_preset_service \
  test_douyin_commerce_batch_service \
  test_task_service \
  test_douyin_commerce_batch_executor \
  test_douyin_commerce_service \
  test_douyin_publish_executor \
  test_douyin_verification \
  test_douyin_verification_dialog
.venv/bin/python desktop_native_app.py --ui-test
```

第二条命令必须输出 `NATIVE_DESKTOP_UI_OK`。两条命令均通过后，才可以进入真实平台预检。

### 二、真实平台预检（不提交）

1. 由已登录用户选择一个账号和两条测试视频，保存并恢复本地批次；再次确认本机保存没有创建任何平台草稿。
2. 为两条视频分别分配已验证的官方地点预设；在 `runtimeMode=preflight`、`debugDryRun=true` 下回读名称、完整地址和平台可读标识，确认每条与其预设精确一致。
3. 核验默认立即发布，以及“起始时间 + 间隔 + 单条覆盖”在客户端汇总、任务载荷和编辑页发布方式中的显示一致；定时值以 Asia/Shanghai 的未来时间为准。
4. 在安全测试环境触发或模拟短信验证，确认客户端暂停整批、重发受 60 秒限制、验证码仅在内存中使用，成功后只从当前条继续；本阶段不能绕过、保存或记录验证码。
5. 二维码、登录失效、验证码、未知合规/风控提示或任何无法唯一确认的控件均应暂停，不得改记为预检通过。

此阶段的证据是编辑页字段与预检回读；它不是草稿、定时任务或公开发布成功的证据。

### 三、用户单独授权后的真实提交

1. 用户在总确认页逐条核对账号、视频、标题、完整地点与发布方式，并单独授权本批次最终提交。
2. 执行真实批量时，立即发布仅凭平台最终发布回执标为已发布；定时发布须再从平台管理页回读标题和指定 Asia/Shanghai 时间，才标为已定时。
3. 单条可诊断失败可记录后继续下一条；全局登录/验证码/二维码/未知提示必须暂停整批并等待用户操作，绝不猜测或自动确认。
4. 只有取得每条平台最终回执后才能写入 `published=true` 或 `scheduled=true`。任务创建、本地保存、上传完成、编辑页回读或 dry-run 均不得替代平台成功。
