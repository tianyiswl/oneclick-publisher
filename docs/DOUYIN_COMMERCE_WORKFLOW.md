# 抖音带货批量工作流

“抖音带货”是独立于多平台发布中心的本地团购视频工作台。首版面向同一抖音账号一次处理 1 至 20 条视频：共享标题、文案、标签、收藏音乐和作品内容声明；每条视频分别指定官方地点与发布时间。

## 用户流程

1. **内容准备**：选择一个状态正常的抖音账号、1 至 20 条本地视频，填写共享标题、文案和标签。内容可只保存在本机，恢复不会创建平台草稿。
2. **平台设置**：选择已同步到本机、且来自该账号“收藏”列表的音乐；选择一项作品内容声明；为每条视频选择完整地址可见的官方地点预设。默认立即发布；也可设定 Asia/Shanghai 的起始时间和间隔，并对单条时间覆盖。
3. **检查与提交**：先逐条进行预检并回读编辑页字段。用户在总确认页检查每条视频、完整地点和发布方式后，才能提交批量发布。

地点预设仅是本机保存的“下次可复用选择”。每一次预检或提交仍会在当前抖音编辑页按范围（国内或本地）重新搜索，并要求名称、完整地址和平台可读标识精确匹配；预设绝不替代真实平台回读。

## 执行顺序与状态

批量执行器每次只处理一条视频，固定顺序为：

`上传 → 写入标题/文案/标签 → 选择收藏音乐 → 选择声明 → 搜索并写入地点 → 写入发布方式 → 预检回读 →（仅已确认发布）最终提交 → 平台管理页回读`。

- 预检始终以 `runtimeMode=preflight` 与 `debugDryRun=true` 执行，绝不会调用最终提交。
- 正式提交必须同时具备 `runtimeMode=publish`、`debugDryRun=false` 和 `batchConfirmed=true`。缺少其中任一项时不创建提交线程。
- 立即发布只有收到平台最终发布回执才标为成功；定时发布还必须从管理页回读标题和指定的 Asia/Shanghai 时间才标为已定时。
- 单条出现可诊断的字段或平台失败时，记录该条失败并继续下一条；二维码、验证码、登录失效、未知合规/风控或控件无法唯一确认时，整批暂停，等待用户处理后从当前会话继续。
- 短信验证码由一键发原生对话框承接。验证码仅在内存中处理；重发受平台最短 60 秒间隔限制，不保存到任务、日志或内容包。

## 载荷与任务记录

批次信封使用：

```text
workflow=douyin-commerce-batch
commerceMode=local-group-buy
```

每条内部操作载荷使用旧单视频的 `workflow=douyin-commerce`，并带 `batchWorkflow=douyin-commerce-batch`。这是执行器内部契约：通用发布服务和旧单视频执行器都会拒绝此类内部条目，不能将逐视频任务误写成一次通用平台成功。

任务记录逐条保存视频名称、完整地点、立即发布或北京时间定时、编辑页预检结果及最终平台回执。不会保存 Cookie、二维码、短信验证码、账号凭据、页面 HTML、原始请求或门店/商品库。

## 明确不支持的范围

- 图文、文字、多账号、跨平台批量；
- 门店绑定、商品/套餐选择和商品库管理；
- 官方 API、签名参数、私有接口或第三方地图数据；
- 自动选择第一首音乐、模糊匹配地点、跳过验证码或把预检当作发布成功。
