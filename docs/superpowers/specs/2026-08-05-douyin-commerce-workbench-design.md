# 抖音带货连续三栏工作台设计

状态：已锁定，待用户审阅后进入实施计划

日期：2026-08-05
范围：一键发开发版的“抖音带货”页面

## 目标

在不改变现有抖音账号、视频上传、平台会话和发布安全边界的前提下，将抖音带货改造成连续的三栏桌面工作台。用户始终能看清本次账号、内容、视频和下一步，不再因旧控件拼接而丢失流程上下文。

## 已锁定范围

- 仅保留现有单账号、单视频、用户自选收藏音乐、官方发布定位、作品内容声明、立即或北京时间定时、预检和最终确认能力。
- 页面固定为三个阶段：`内容准备`、`平台设置`、`检查与提交`。
- 第 1 页和第 2 页均使用连续三栏：左为发布对象与本地恢复，中为当前阶段操作，右为视频或本次上传会话。
- 上传前本地保存内容；上传后仅维持同一临时编辑会话。放弃本次上传只关闭临时会话，不删除本地保存内容。
- 定位确认后只显示名称和完整地址卡；用户点击“更换定位”才重新出现范围、关键词和候选列表。
- 地点范围或关键词变化时，清空旧定位以及后续声明确认，避免跨范围复用。
- 每个阶段同一时刻只显示一个主操作。次要操作不与主操作竞争注意力。
- 不新增门店绑定、商品选择、图文/文字带货、批量账号或其他平台能力。
- 本轮不执行真实上传、保存草稿、预检或发表；仅完成本地 UI 和交互验收。

## 页面结构

### 1. 内容准备

左栏为发布对象：当前唯一且状态正常的抖音账号、本地内容保存状态、恢复按钮和最近使用标签。

中栏为内容：标题、必填文案、已添加标签、添加标签入口与保存本地内容反馈。保存只写本机 SQLite，不访问平台。

右栏为视频：当前唯一视频、时长与尺寸、替换入口，以及上传后的能力提示。

底部操作条固定显示当前完成条件。唯一主操作为“上传视频并继续”；账号、视频或必填文案不完整时，明确显示缺失项并保持不可执行。

### 2. 平台设置

三栏空间不变。左栏继续显示账号和已保存内容；存在临时编辑会话时，“恢复已保存内容”保持不可用并说明必须先放弃本次上传，避免覆盖已上传会话。中栏按真实编辑页顺序推进：用户选择收藏音乐、选择本地或国内定位、确认完整地址、选择并写入作品内容声明、设置立即或未来北京时间定时；右栏切换为“本次上传会话”，显示视频、音乐、定位、声明和发布方式的完成清单。

平台设置页的主操作严格串行：

1. 读取收藏音乐或确认选中的音乐；
2. 搜索并确认发布定位；
3. 确认写入作品内容声明；
4. 设置立即发表或未来定时；
5. 进入检查。

系统不会默认选择音乐、定位或声明。平台回读成功前，不把步骤标记为完成。

### 3. 检查与提交

检查页集中展示：账号、视频、标题与文案摘要、用户所选音乐、完整地点地址、作品内容声明、立即/定时发表及定时时间。每项均显示“未完成”“处理中”或“已由平台回读确认”。

预检只验证当前编辑页和任务载荷，不保存草稿、不提交发布。最终提交按钮仅在预检通过后可用，文案随立即/定时发表变化。

## 状态与恢复

每页顶部仅显示三段进度。已完成为绿色，当前阶段为蓝色，其余为中性；不使用长段帮助文案取代状态。

右栏会话清单只显示：视频、音乐、定位、声明、发布方式。每项都有状态，不额外创建“本次任务”侧栏。

错误落在触发它的卡片内，呈现“失败原因”和“下一步动作”。自动化底层原始错误仅写入本地诊断日志，不直接弹给用户。

以下错误必须安全停止后续步骤：账号不正常、视频上传会话失效、音乐或定位候选不唯一、地点完整地址未回读、声明回读不一致、定时时间不是未来北京时间、未知平台弹窗或登录/验证码。

## 数据与安全边界

- 继续复用现有本地 draft service，保存账号引用、视频引用、标题、文案、标签和更新时间。
- 本地草稿不得保存 Cookie、二维码、平台临时会话、音乐/地点原始请求或平台凭据。
- 会话状态只存在本次受控编辑流程中。任务创建、预检、定时提交和公开发布仍需分别由平台回读确认。

## 实施边界

本次只调整以下层次：

- `ui/douyin_commerce_page.py`：页面区块、状态映射、按钮可用性、错误显示和恢复交互。
- `ui/common.py`：三栏工作台所需的共享样式，不承载平台业务逻辑。
- `app_core/douyin_commerce_draft_service.py`：仅在必要时补齐本地恢复和标签历史接口。
- 对应测试：本地草稿、页面状态转换、步骤门槛与回读条件。

不修改发布执行器的真实平台选择器、账号登录、上传、草稿或发表逻辑。

## 验收标准

1. 内容准备页可保存并恢复账号、视频、标题、文案和标签；恢复不触发平台动作。
2. 保存内容后，最近使用标签可再次回填当前标签输入。
3. 页面在上传前后保持三栏结构，右栏从视频素材平滑切换为本次上传会话。
4. 音乐、定位、声明和定时严格按步骤解锁，未完成步骤不能进入检查。
5. 确认定位后，候选列表收起，完整地址和更换入口清楚可见。
6. 更换定位范围或关键词后，旧定位与声明确认失效。
7. 放弃本次上传后，临时会话被安全关闭，本地保存内容仍可恢复。
8. 通过离线状态测试、Qt 页面交互测试、开发版两页截图和人工完整路径检查后，才可报告界面改造完成。
