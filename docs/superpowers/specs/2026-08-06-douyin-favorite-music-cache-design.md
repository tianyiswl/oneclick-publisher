# 抖音带货收藏音乐本地缓存设计

## 目标

减少抖音带货每次进入平台设置时重新扫描收藏音乐列表的等待时间。用户可立即从本机看到上次已同步的候选；实际选择仍必须在当前抖音编辑会话中写入并回读。

## 范围与边界

- 仅适用于“抖音带货”的收藏音乐。
- 缓存按已登录抖音账号隔离，不能跨账号复用。
- 仅保存音乐 ID、标题、作者、时长、更新时间和账号标识。
- 不保存 Cookie、二维码、会话、页面原始 HTML、网络请求或音乐封面地址。
- 不使用官方 API、私有接口或签名参数。
- 不自动打开浏览器或自动刷新。用户点击“刷新收藏音乐”时，才从当前已上传的无头编辑会话读取。

## 交互

1. 视频上传完成后进入“平台设置”。
2. 音乐下拉框优先展示该账号的本地缓存；没有缓存时显示“暂无本地收藏音乐”。
3. 用户可点“刷新收藏音乐”，从当前抖音编辑页读取一次收藏列表并更新本地缓存。
4. 用户从下拉框选择音乐后，一键发在同一编辑会话打开音乐选择器，仅定位该音乐 ID 对应的唯一条目，写入并回读。
5. 若缓存音乐在当前平台列表中不存在、身份重复、控件变化或回读不一致，安全停止并提示“收藏音乐缓存已过期，请刷新”，不改选其他音乐。

## 数据与接口

新增本地表 `douyin_favorite_music_cache`：

- `accountKey`：账号隔离键。
- `musicId`：平台可回读音乐标识。
- `title`、`creator`、`duration`：下拉框显示信息。
- `syncedAt`：本次同步时间。

唯一键为 `(accountKey, musicId)`。刷新采用事务性替换该账号的完整候选集；选择成功后更新该音乐的最近使用时间（如现有表字段允许），不保存瞬态页面 marker。

会话层新增：

- 读取本地缓存候选。
- 用户触发刷新后，把当前编辑页已验证的候选写入缓存。
- 选择缓存音乐时，重新从当前编辑页定位同一 `musicId`；不把缓存直接当作平台已写入证据。

## 失败处理

- 当前会话不存在或视频未上传：不读取、不刷新，提示先完成上传。
- 登录失效：保持无头，不自动登录；提示到账号管理重新登录。
- 缓存为空：用户可刷新；不默认选择第一首。
- 平台候选和缓存不一致：要求刷新，不猜测相近标题。
- 写入或回读失败：保留原选择状态，不把任务标记为已完成或已发布。

## 验证

- 离线测试：账号隔离、缓存写入/覆盖、无缓存、缓存过期、重复音乐拒绝、只显示安全字段。
- 会话测试：缓存可立即显示；最终写入仍需当前编辑页唯一匹配并回读。
- UI 测试：首次无缓存、手动刷新、缓存下拉选择、过期提示。
- 不进行真实发布、草稿保存或账户设置变更。

## 不包含

- 自动后台周期同步。
- 跨账号推荐或共享收藏音乐。
- 音乐搜索、下载、音频上传、版权判断或收藏夹管理。
