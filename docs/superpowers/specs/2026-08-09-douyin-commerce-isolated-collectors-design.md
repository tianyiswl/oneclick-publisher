# 抖音带货平台设置隔离采集会话设计

状态：用户已确认

日期：2026-08-09
范围：一键发开发版「抖音带货」的平台设置采集、批次生命周期、正式发布应用与诊断验证

## 1. 背景与根因

当前平台设置把收藏音乐、国内地点和本地点放在同一个抖音编辑会话中完成。地点检索还会调用收藏音乐刷新作为位置组件“预热”，本地与国内范围也在同一地点面板中来回切换。

这条路线已经暴露出以下结构性问题：

1. 打开音乐抽屉或切换地点范围会重绘发布页局部 DOM，旧输入框、候选列表和范围控件随即失效。
2. 同一页面残留的下拉浮层会干扰带货模式和地点范围的唯一回读。
3. 第一次操作成功后，后续搜索可能继续持有旧 marker、旧 locator 或旧候选列表。
4. 批次正常完成、途中放弃、异常停止或重新登录后，旧会话生命周期边界不够强，下一批可能继承不可见的页面状态。
5. 当前错误信息多为最终症状，无法快速区分音乐、国内地点、本地点、平台频控、账号验证还是清理不完整。

此前针对 DOM 重绘、浮层残留和候选识别的局部修复仍然保留价值，但它们不能消除“多个功能共享一个易变页面”这一根因。本设计以会话隔离替代功能间预热和范围切换。

## 2. 目标

1. 收藏音乐、国内地点、本地点使用三个互不共享页面状态的临时采集会话。
2. 国内采集器进入平台设置时自动启动；音乐和本地采集器只在用户点击相应功能时启动。
3. 同一批次内允许重复搜索和任意功能顺序，但所有浏览器动作串行执行，避免并发操作触发平台混乱或频控。
4. 第一批完成、途中放弃、异常中止、重新登录和客户端重启后，旧会话都不能进入下一批。
5. 采集结果只作为本地待应用配置；正式发布必须在每条视频的全新发布会话中重新应用并精确回读。
6. 单个采集器故障可受控重建，不要求用户重启整个客户端。
7. 日志能够回答“哪一批、哪种采集器、哪个关键词、在哪个阶段、为什么失败、是否清理完成”。

## 3. 非目标与安全边界

- 不调用抖音私有接口、签名参数或非页面能力。
- 不保存 Cookie、二维码、验证码、页面 HTML、原始网络请求或账号凭据。
- 不把缓存候选、本地选择、临时编辑页上传或字段点击写成正式发布成功。
- 不在自动回归中点击最终提交，不创建草稿，不公开发布。
- 不通过无限重试、并发轰击或快速重复刷新规避平台频控。
- 不在本轮重构海外平台、普通抖音发布或其他国内平台流程。

## 4. 已锁定方案

采用同一客户端进程内的三个独立 Playwright `BrowserContext + Page + Session`：

| 采集器 | 启动方式 | 固定职责 | 生命周期 |
| --- | --- | --- | --- |
| `DomesticLocationCollector` | 进入平台设置自动启动 | 只读取国内地点候选 | 平台设置期间保持存活 |
| `FavoriteMusicCollector` | 点击“刷新音乐”时懒启动 | 只读取收藏音乐候选 | 创建后保持存活，批次结束关闭 |
| `LocalLocationCollector` | 首次本地搜索时懒启动 | 只读取本地点候选 | 创建后保持存活，批次结束关闭 |

三个 Context 可以由同一份已保存账号登录状态创建，但不共享实时 DOM、Page、locator、浮层状态或内存 Session。登录状态只作为代际创建时的只读种子；若任一采集器发现登录失效或账号验证，整个代际安全暂停并要求在账号管理重新登录，不把某个 Context 的临时认证变化传播给其他 Context。

不采用以下路线：

- 三个功能共用一个 Page：无法隔离抽屉与地点面板重绘。
- 一个 Context 内开三个 Page：Cookie 和部分浏览器存储仍会实时互相影响，隔离不足。
- 三个独立子进程：隔离最强，但首期进程通信、崩溃恢复和打包维护成本过高。

## 5. 总体架构

### 5.1 `SetupGenerationCoordinator`

每次进入平台设置都创建唯一 `setupGenerationId`，并持有：

- 当前账号脱敏标识；
- 当前代际状态；
- 三个采集器实例引用；
- 全局 `CollectorActionQueue`；
- 本地待应用配置 `LocalStagedConfig`；
- 取消令牌和清理结果；
- 结构化诊断上下文。

任何异步回调写入 UI 或配置前必须同时满足：

```text
callbackGenerationId == activeGenerationId
collectorState == ACTIVE
generationState in {COLLECTING, READY}
```

条件不满足时，结果只能记录为 `stale_result_discarded`，不得修改 UI、覆盖选择或启动下一步。

### 5.2 `CollectorActionQueue`

三个采集器拥有独立浏览器会话，但浏览器动作通过同一个队列串行执行：

- 同一时间只允许一个刷新、搜索、重试或关闭前页面动作；
- 每个动作有独立 `requestId`、超时和有限重试策略；
- 用户触发的新动作可以排队，但不能并发操作平台；
- 清理开始后拒绝新动作，并取消尚未执行的队列项；
- 平台出现频控、账号验证或结构性歧义时停止自动重试。

这样既保留 DOM 隔离，又避免三个页面同时请求平台。

### 5.3 内置探针视频

采集器需要进入抖音临时编辑页时，使用应用内置的轻量、非敏感探针视频：

- 探针是有效 MP4，不包含用户素材、账号信息、二维码或业务内容；
- 每种采集器每个代际最多创建一个临时编辑页；
- 国内采集器进入平台设置时创建；音乐和本地采集器按需创建；
- 采集结束优先执行受控“放弃本次上传”，随后关闭 Page 和 Context；
- 放弃动作失败时仍关闭 Context，并记录 `cleanup_incomplete`，绝不点击最终提交；
- 探针上传成功只表示临时编辑页可用，不表示草稿、定时或发布成功。

### 5.4 `LocalStagedConfig`

所有候选和用户选择先进入本地待应用配置：

- 收藏音乐选择；
- 每条视频对应的完整地点；
- 作品声明；
- 发布方式、北京时间日期和逐条间隔；
- 每项来源、选择时间和候选版本。

数据状态必须区分：

- `candidate`：采集器返回的候选；
- `selected_local`：用户在客户端完成选择；
- `applied_to_publish_page`：正式发布页已执行写入；
- `readback_confirmed`：正式发布页精确回读一致；
- `platform_receipt_confirmed`：最终提交后取得平台回执。

前一状态不能推断后一状态。

账号级音乐缓存和地点预设可以持久化，但只能恢复为 `candidate`，不能自动恢复为 `selected_local`、`readback_confirmed` 或平台成功。

## 6. 功能流程

### 6.1 进入平台设置

1. 先对任何旧代际执行统一 `cancel-and-close`。
2. 创建新的 `setupGenerationId` 和动作队列。
3. 从当前账号登录状态创建国内采集器。
4. 国内采集器上传探针视频并固定在“国内”范围。
5. UI 显示国内采集器状态；音乐和本地显示“尚未启动”。
6. 国内地点搜索按视频顺序串行执行，不通过音乐刷新预热位置组件。

### 6.2 刷新收藏音乐

1. 用户点击“刷新音乐”。
2. 若本代际没有音乐采集器，创建独立 Context、上传探针并进入收藏音乐能力页。
3. 关闭该页面自己的旧音乐抽屉，再打开并读取收藏列表。
4. 候选规范化、去重后写入账号级缓存和当前代际候选。
5. 关闭音乐抽屉；音乐采集器保留到批次结束或故障重建。
6. 全流程不访问国内或本地点页面。

### 6.3 搜索本地点

1. 用户首次执行本地搜索。
2. 创建独立 Context、上传探针并固定在“本地”范围。
3. 之后所有本地关键词只路由到该采集器。
4. 该采集器不切换到国内；国内搜索始终路由到国内采集器。
5. 关键词清空、重新输入、候选关闭和回读只影响本地采集器自己的页面。

### 6.4 正式发布关闭屏障

用户通过“检查并继续”进入正式发布前，必须完成：

1. 代际从 `READY` 转为 `CLOSING_COLLECTORS`，禁止新采集动作。
2. 取消排队动作并等待当前动作在有限时间内收尾。
3. 三个采集器分别执行放弃临时上传并关闭 Page、Context。
4. 确认存活采集器数量为零、动作队列为空。
5. 撤销 `setupGenerationId` 的采集写权限，但保留该编号作为只读审计关联，状态转为 `PUBLISHING`。
6. 只有关闭屏障成功后才允许创建正式发布会话；关闭不完整则安全停止并显示诊断，不混用临时页面继续发布。

### 6.5 每条视频正式发布

每条视频串行使用全新的正式发布 `BrowserContext + Page`：

1. 上传本条用户视频并回读标题、文案。
2. 在填写前清理当前页面可能存在的旧值并回读空值或目标基线。
3. 一次性应用该视频对应的音乐、地点、声明和定时设置。
4. 每项都从当前正式发布页重新定位唯一控件并精确回读。
5. 任一项不一致时，本条安全停止并记录具体阶段；不得借用采集器回读结果作为正式页成功证据。
6. 沿用现有最终确认门和平台回执判断。
7. 本条完成、失败或待核对后关闭正式发布会话，再处理下一条。

## 7. 批次生命周期

代际状态机为：

```text
NEW -> COLLECTING -> READY -> CLOSING_COLLECTORS -> PUBLISHING -> CLOSED
                   \-> CANCELLING ---------------------------> CLOSED
                   \-> PAUSED_FOR_LOGIN ---------------------> CLOSED
```

不允许从 `CLOSED` 回到任何活动状态，也不允许从 `PUBLISHING` 回到采集阶段。

### 7.1 统一 `cancel-and-close`

正常完成、途中放弃、异常中止、重新登录和客户端退出共用同一条清理链：

1. 将代际标记为 `CANCELLING` 或 `CLOSING_COLLECTORS`，先禁止新动作。
2. 取消尚未执行的队列项。
3. 给正在执行的动作一个短时收尾窗口，超时后强制进入关闭。
4. 各采集器尽力放弃临时上传，再依次关闭 Page 和 Context。
5. 清空内存 Session ID、locator、DOM marker、临时候选和当前批次选择。
6. 释放探针文件引用，统计仍存活的采集器。
7. 写入清理结果，代际转为 `CLOSED`。

### 7.2 各结束事件的数据处理

| 事件 | 当前批次选择 | 账号级缓存/预设 | 下一次进入 |
| --- | --- | --- | --- |
| 正常发布完成 | 清空 | 保留为未确认候选 | 创建全新代际 |
| 途中放弃 | 清空，不自动恢复 | 保留为未确认候选 | 从 `NEW` 开始 |
| DOM/平台异常 | 当前页只保留脱敏诊断，离开后清空 | 不覆盖已有有效缓存 | 故障页面不得复用 |
| 重新登录/切换账号 | 清空 | 按账号隔离 | 登录后创建全新代际 |
| 客户端重启/崩溃恢复 | 不恢复进行中选择 | 只加载持久化候选 | 不恢复旧 Session ID |

## 8. 错误处理与受控重试

错误按阶段和责任域分类：

- `collector_start_failed`：探针上传或临时编辑页创建失败；
- `login_required`：登录失效、验证码或账号验证；
- `scope_not_confirmed`：国内或本地范围无法唯一回读；
- `candidate_panel_missing`：候选面板未出现；
- `candidate_ambiguous`：存在多个有效面板或目标不唯一；
- `candidate_empty`：平台返回空候选；
- `rate_limited_or_degraded`：连续有限等待后平台仍不生成能力控件；
- `stale_result_discarded`：旧代际或已关闭采集器的迟到结果；
- `cleanup_incomplete`：放弃或关闭未完整完成；
- `publish_apply_mismatch`：正式发布页写入与回读不一致。

单个采集器失败时，UI 提供“重试当前采集器”：

1. 先销毁故障采集器；
2. 在当前代际内创建同类型新实例；
3. 保持其固定职责和固定范围；
4. 不重建其他健康采集器，不借用其他页面；
5. 不无限重试。结构歧义、账号验证或疑似频控时安全停止，等待人工处理。

账号验证出现时，整个代际进入 `PAUSED_FOR_LOGIN`，停止批量动作。重新登录后关闭旧代际并从内容准备或新平台设置代际重新开始。

## 9. 诊断日志与客户端展示

每个采集和发布动作输出结构化字段：

- `timestamp`
- `requestId`
- `setupGenerationId`
- `collectorType`
- `collectorInstanceId`
- `accountMaskedId`
- `phase`
- `action`
- `scope`
- `keyword`
- `attempt`
- `candidateCount`
- `durationMs`
- `outcome`
- `errorCode`
- `cleanupResult`

日志不得包含 Cookie、二维码、验证码、完整账号凭据、页面 HTML 或原始请求。

客户端平台设置页增加轻量诊断状态：

- 当前批次代际短编号；
- 国内、音乐、本地三个采集器的 `未启动/启动中/可用/重试中/失败/已关闭`；
- 当前动作、关键词、候选数量和耗时；
- 具体失败阶段和错误码；
- “复制诊断摘要”，默认脱敏。

批量任务明细继续逐视频展示应用、回读、提交和平台回执结果，不用总数掩盖具体失败视频。

## 10. 测试设计

### 10.1 L1 状态机单元测试

- 新代际创建前关闭旧代际；
- 状态转换合法性；
- `CLOSED` 不可恢复；
- 迟到回调被丢弃；
- 队列取消、动作超时和强制关闭；
- 正常完成、放弃、异常、重登录和重启的数据清理；
- 缓存按账号隔离并只恢复为候选。

### 10.2 L2 浏览器契约测试

- 三个采集器拥有不同 Context、Page 和实例编号；
- 音乐抽屉重绘不改变国内/本地采集器 locator；
- 国内和本地范围分别固定，不在同一 Page 切换；
- 模拟面板重绘、旧浮层、多候选、空候选和输入框失效；
- 重建故障采集器不影响另外两个实例；
- 正式发布会话不能访问采集器 DOM 或 Session。

### 10.3 L3 客户端集成测试

- 进入平台设置只自动启动国内采集器；
- 音乐和本地按钮首次点击才创建对应采集器；
- 任意操作顺序都路由到正确采集器；
- 放弃后 UI 和当前选择重置，缓存仍以候选展示；
- 单采集器重试无需重启客户端；
- 诊断状态和复制摘要不泄露敏感信息；
- 关闭屏障未完成时不能进入正式发布。

### 10.4 L4 抖音实机预提交回归

使用内置探针视频，不使用批量用户内容，不进入最终提交：

1. 冷启动后连续搜索 20 条国内地点；
2. 验证三组顺序：音乐→国内→本地、国内→音乐→本地、本地→国内→音乐；
3. 国内与本地各自重复搜索，不在同页切范围；
4. 正常结束代际 A，再创建代际 B 重复核心流程；
5. 代际中途放弃，再进入新代际重复核心流程；
6. 人为关闭一个采集 Page，验证只重建对应采集器；
7. 在搜索中关闭旧代际，验证迟到结果不写入新代际；
8. 验证所有探针编辑页已放弃并关闭，最终提交次数为零。

若实机出现验证码、账号验证、疑似频控或页面能力长期缺失，立即停止，不通过高频重试扩大账号风险。

### 10.5 正式发布验证边界

自动测试和探针预提交只能证明采集、隔离和清理正常，不能证明正式发布成功。真实单条正式发布验证必须由 Andy 另行明确确认；需保存本条字段回读、平台提交回执和作品管理页结果三层证据，不能用本地测试或探针成功替代。

## 11. 验收门槛

只有同时达到以下条件，才能宣布平台设置隔离重构完成：

1. 新增状态机、隔离会话、动作队列、清理、回读和诊断测试全部通过，现有完整测试无回归。
2. `py_compile`、离屏 `desktop_native_app.py --ui-test` 和 `git diff --check` 通过。
3. 同一客户端连续完成两个平台设置代际；其中一轮正常结束，另一轮中途放弃后重来。
4. 两轮均覆盖音乐刷新、20 条国内地点和多次本地点搜索。
5. 旧 Session 复用数为 0。
6. 迟到结果写入新批次数量为 0。
7. 代际结束后的存活采集器数量为 0。
8. 国内/本地跨页串用数量为 0。
9. 探针最终提交、草稿和公开发布数量为 0。
10. 日志可以明确定位每个失败动作、采集器、关键词、阶段和清理结果。

## 12. 迁移与兼容策略

1. 保留现有 DOM 唯一性、完整地址规范化、候选回读和失败安全停止规则，并下沉为单个采集器可复用能力。
2. 删除地点搜索调用收藏音乐刷新的预热依赖。
3. 删除单一采集 Page 内的本地/国内往返切换路径；两个范围分别由固定采集器负责。
4. 平台设置阶段不再复用批量第一条用户视频的正式发布会话。
5. 旧平台设置 Session ID 不迁移到新代际；升级或重启后统一视为已关闭。
6. 账号级音乐缓存和地点预设保留，但统一标记为未确认候选。
7. 不同时运行旧共享会话路线和新隔离路线，避免同一批次出现两套状态来源；需要回退时通过 Git 版本回退，而不是运行时混用。
