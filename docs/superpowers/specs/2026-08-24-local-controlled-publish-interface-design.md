# 一键发本地受控发布接口与 008 兼容修复设计

## 1. 目标

内容项目生成结构化发布包后，Codex 可以直接调用一键发完成预检、回读任务，并在用户于当前对话中明确确认后继续正式发布。用户不需要再逐项点击桌面客户端；只有验证码、平台风控或必须人工操作的控件出现时才唤起原生窗口。

本轮同时修复硅基探索 008 暴露的四个问题：国内任务误显示海外文案、预览 Markdown 污染发布正文、抖音旧正文无法清空、小红书视频封面入口失效。

## 2. 用户流程

1. Codex 调用本地 CLI 创建 `preflight` 任务，输入内容包 manifest、明确账号和各平台发布时间。
2. CLI 返回稳定 JSON；Codex轮询任务状态并在对话中逐平台报告预检结果。
3. 用户回复“确认发布”后，Codex为这次预检创建一次性授权记录。授权绑定内容包指纹、账号、平台、发布时间和预检任务，短期有效且只能消费一次。
4. Codex调用 `formal`，后台复用同一发布服务执行，并继续轮询 JSON 状态。
5. 只有平台要求验证码、风控确认或人工选项时才显示原生窗口；这些状态不得冒充失败或成功。

没有用户本次明确确认时，接口默认且只能执行预检。授权记录不包含 Cookie、密码或平台凭据。

## 3. CLI 合同

入口：`desktop_native_app.py --controlled-publish ...`

### 3.1 创建任务

请求从 UTF-8 JSON 文件或标准输入读取，禁止把授权、Cookie、密码放入命令行参数。核心字段：

- `manifestPath`：内容包 manifest 绝对路径；
- `mode`：`preflight` 或 `formal`，缺省为 `preflight`；
- `targets`：平台、明确的一键发账号 ID、发布方式和该平台 schedule；
- `confirmedPreflightTaskId`：正式任务必填；
- `authorizationId`：正式任务必填的一次性本地授权记录 ID。

返回字段至少包含：`taskId`、`mode`、`phase`、`status`、逐平台 `platform/accountId/status/errorCode/errorText/receipt/contentId/scheduledAt`。

### 3.2 查询任务

通过 task ID 只读查询 SQLite 中的任务与逐平台结果。预检成功只表示字段和页面回读通过；正式提交、定时成功和公开发布分别使用不同状态。

### 3.3 授权

授权命令只接受已经完成且可正式继续的预检 task ID，并从该任务快照生成授权范围。授权写入本地数据库，默认 10 分钟有效、一次消费；不能修改账号、平台、正文或发布时间后复用。

## 4. 共用发布服务

新增受控请求归一化层和服务层，桌面 UI 与 CLI 都把请求转成同一 `publish_service` 输入，不复制执行器。CLI 的后台 worker 使用独立进程继续现有 SQLite 任务，避免创建命令退出后守护线程被终止。

授权校验位于服务层而不是 UI/CLI：任何正式入口都必须验证预检已完成、请求指纹一致、授权未过期且未消费；校验与消费在同一数据库事务中完成。

## 5. 内容包规则与旧包迁移

发布字段必须分开保存：标题、正文、@提及、#话题、封面、AI 声明和平台覆盖。`正文.md` 可以是给人看的预览，但不能在存在完整平台覆盖时自动写入通用正文。

导入优先级：

1. 平台覆盖中的结构化字段；
2. manifest 中的结构化通用字段；
3. 只有旧包没有任何结构化正文时，才显式迁移旧 `bodyFile`，并拒绝包含 `## 抖音`、`## 小红书` 等平台预览章节的文件。

旧 AI 声明 `{text,image,video,audio}` 显式迁移为当前 `containsAiGeneratedContent/contentKinds/assetPaths/allowPlatformAutoDeclaration`；无法无损迁移时返回固定错误，不能静默丢字段或污染正文。

## 6. 四项真实问题修复

### 6.1 国内按钮文案

预检结束按钮根据任务实际平台生成：仅国内显示“继续正式发布”，包含海外且满足条件时才显示“继续海外平台正式发布”。测试覆盖国内、海外和混合任务。

### 6.2 抖音正文清空

导入器不再注入预览 Markdown。编辑器清空同时使用运行平台对应快捷键：macOS 使用 `Meta+A`，Windows/Linux 使用 `Control+A`；每次清空后必须回读为空，再写入一次目标正文。

### 6.3 小红书封面

封面入口使用当前真实页面可见控件、文字和层级组合定位，并在唯一候选出现后点击和回读。找不到时记录页面阶段、可见候选数和固定错误码，不把预检当成已经定时或发布。

### 6.4 008 时间语义

抖音可立即发布，小红书可在同一请求中指定 `2026-08-24 20:30`。内容包本身不强行写死运行日期；请求快照和任务结果保存最终 schedule。

## 7. 安全与状态边界

- CLI 不接受 Cookie、密码、验证码或二维码链接；
- 日志不记录授权原文、敏感凭据、内容全文或平台登录数据；
- 预检、正式提交、平台定时成功、公开发布是四个不同结果；
- `debugDryRun=true` 或 `publishAllowed=false` 的内容包不能被正式发布，除非生成了明确迁移后的可发布包并再次预检；
- 本轮真实验收只执行 008 预检，正式公开发布仍需用户在预检结果后再次确认。

## 8. 验收

- 国内、海外和混合预检按钮文案测试通过；
- 008 结构化导入后通用正文不含 Markdown 章节，标题、正文、@、# 不重复；
- 旧 AI 声明得到显式迁移或固定错误；
- CLI 能创建预检、查询 task ID、生成一次性授权，并拒绝过期、重复或篡改后的正式请求；
- 抖音 macOS 清空旧正文回归测试通过；
- 使用当前小红书登录页面完成一次视频封面入口回读预检；
- 使用 008 包分别报告抖音和小红书预检结果，不越级报告定时或公开发布。
