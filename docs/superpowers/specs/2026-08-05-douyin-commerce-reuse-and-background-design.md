# 抖音带货内容复用与后台会话设计

## 目标

让“抖音带货”的内容准备与平台设置成为同一条可恢复流程：用户改标题、文案或标签时，不重复登录、不重复上传视频；仅账号或视频变化才重新建立上传会话。平台设置保持简洁的双栏操作，不展示重复的回读证据或固定说明文字。

## 页面结构

平台设置页不保留固定介绍段落。页面仅保留步骤条、四个设置区域、动态错误/同步状态和底部唯一主操作。

- 左栏：收藏音乐、作品内容声明。
- 右栏：发布定位、定时发布。
- 底部：检查并继续。

四项可任意操作，客户端继续沿用“选择后写入当前编辑会话并回读”的行为，但不在界面重复写出该事实。

### 简化规则

- 删除“已由当前抖音编辑页回读确认”。
- 删除“已确认一首收藏音乐”。
- 删除声明、音乐、定位成功后的重复说明卡片；保留用户实际选中的音乐、完整地点地址、声明选项和定时时间。
- 只在同步中、失败或需人工处理时展示一行短提示。

## 内容变更模型

上传成功后记录一份仅用于判断的编辑会话快照：

- 上传身份：`accountId/accountFile` 与 `mediaId/mediaPath`。
- 可同步内容：标题、文案、标签。
- 会话：当前抖音编辑页对应的内存会话标识。

回到“内容准备”后的动作按差异处理：

| 变化 | 客户端动作 | 平台动作 |
| --- | --- | --- |
| 无变化 | 继续平台设置 | 无浏览器、无上传、无写入 |
| 仅标题、文案、标签变化 | 同步内容并继续 | 在现有编辑页写入并回读标题、文案、标签；不上传视频、不登录 |
| 账号或视频变化 | 重新上传视频并继续 | 关闭旧编辑会话，重新核对账号并上传新视频 |

若编辑会话已关闭、过期或平台无法回读，内容同步不伪装成功；客户端提示用户重新上传后继续。该安全回退不是由文字改动触发，而是由会话不可用触发。

## 浏览器策略

内容同步和首次上传默认使用后台浏览器会话，不抢占桌面前台。上传进度仍在客户端任务区域展示。

只有遇到登录失效、二维码、验证码或平台要求人工处理的异常时，才前台展示对应浏览器页面并停止自动操作。此设计不改变“不保存草稿、不预览、不发表”的现有边界。

## 实现边界

- 不改变音乐、定位、声明、定时的真实平台选择器与安全停机策略。
- 不新增草稿、自动提交或发表行为。
- 不把本地表单值写成平台已保存状态；内容同步、即时设置和后续检查仍以编辑页回读为准。
- 不修改账号凭据、storage state 格式或内容包。

## 验收

### 离线

- 标题/文案/标签任一变化只走内容同步路径，不调用视频上传。
- 账号或视频变化必须关闭旧会话并走上传路径。
- 无变化不调用浏览器会话或平台写入。
- 会话不可用时内容同步安全失败，且不记录为已同步。
- 上传上下文默认后台；需要人工登录/二维码时返回可前台处理的受控状态。
- 平台设置区域顺序为“音乐、声明 / 定位、定时”，且没有固定介绍与重复确认文案。

### 客户端

- 修改标题后返回平台设置，不出现浏览器窗口和视频重传进度；标题在同一编辑会话中回读。
- 不修改任何内容时返回平台设置，不出现浏览器窗口和任何平台动作。
- 更换账号或视频后，才显示新的后台上传进度。
- 登录失效、二维码、验证码出现时，客户端明确提示并将对应页面交给用户处理。
