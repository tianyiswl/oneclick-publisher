# 硅基进化公众号自动草稿桥接设计

日期：2026-08-25  
状态：已获产品方向确认，待实施前复核

## 目标

让正在运行、且已登录硅基进化公众号的一键发桌面端，接收内容系统已经冻结的 V1.2 发布包，自动保存为公众号后台草稿，并回读草稿列表确认结果。

第一期的终点只能是“草稿已由后台列表回读”。不自动发表、不群发、不设定时发表、不读取或导出 Cookie、二维码、Token 与账号密码。

## 已核实的起点

- 硅基进化当前发布包是不可变 V1.2 包，包含 `release-manifest.json`、`publication.json`、`content.html`、封面和正文图片；它不是旧版 `oneclick-wechat-content/v1` 导入包。
- 一键发现有公众号正式发表执行器和编辑页预检，但其“保存平台草稿”当前只支持视频号和 B 站；公众号草稿保存会被拒绝。
- 不能把现有 `runtimeMode=publish` 的执行器当草稿通道使用，也不能把一次预检说成草稿保存成功。

## 设计

### 1. 交接记录

内容系统只在文章处于 `delivered_unverified` 后，原子写入一份本地交接记录。记录只包含：

- `article_id`；
- V1.2 发布包绝对路径；
- 冻结包 SHA-256；
- 目标账号的稳定显示名 `硅基进化`；
- `intent: wechat_draft_only`；
- 创建时间与格式版本。

交接记录不含账号 ID、Cookie、二维码、Token、正文副本或任何发表开关。一键发必须重新读取发布包，而不是信任交接记录中的正文。

每篇文章最多一份活动交接记录。未运行桌面端、桌面端未登录或草稿保存失败时，记录保留失败原因和时间，不自动重复提交。

### 2. 一键发导入与校验

新增 V1.2 发布包导入器，仅接受已冻结的本地发布包。导入器必须：

1. 读取并校验 `release-manifest.json` 的文件清单和哈希；
2. 要求 `state=release_ready`、`publish_allowed=false`，并要求 `publication.json` 的 `article_id`、标题和摘要有效；
3. 验证封面、正文图片和 `content.html` 都位于包内；
4. 把包哈希、文章 ID、标题和导入时间写入本地任务；
5. 拒绝路径越界、重复文章 ID、已失效交接记录或任何缺失文件。

导入后的编辑器载荷只用于“保存草稿”。它不携带 `runtimeMode=publish`、群发通知、定时发表或最终发表确认字段。

### 3. 公众号草稿执行器

新增独立的 `wechat_draft_executor`，与正式发表执行器分开。它复用一键发的本机浏览器会话、账号检查和二维码验证界面，但只能执行以下动作：

1. 打开公众号图文编辑页；
2. 回读当前编辑账号必须为硅基进化；
3. 填写并回读标题、摘要、正文、封面和正文图片；
4. 点击唯一、已知的“保存草稿”控件；
5. 打开草稿列表，按文章 ID 映射的标题和本次时间精确回读草稿；
6. 写入不含凭据的草稿回执。

页面出现未知弹窗、登录失效、二维码验证、账号不一致、控件不唯一、字段回读不一致、保存后找不到草稿，或草稿标题不唯一时，执行器必须停止并标为失败。二维码只能在一键发原生窗口中由大帅扫码，绝不保存图片或链接。

### 4. 队列与回执

一键发仅在桌面端运行时扫描已配置的本地交接目录；默认关闭，首次启用前必须在界面明确显示“只保存草稿，不会发表”。

每次处理后，一键发原子写出对应回执：`article_id`、包哈希、账号显示名、状态（`draft_readback_confirmed` 或失败）、时间和安全错误码。成功回执不等于发表。

内容系统只消费匹配 `article_id + package_sha256` 的成功回执，并把它记为新的协作证据 `wechat_draft_readback_confirmed`；不复用历史 `draft_created` 状态，也不改变 `delivered_unverified`、`manually_published_user_confirmed` 或 `manually_published` 的含义。

## 数据流

```text
V1.2 冻结发布包
  -> 草稿交接记录（只含路径、文章 ID、哈希）
  -> 一键发重新校验包
  -> 公众号后台保存草稿
  -> 草稿列表精确回读
  -> 本地安全回执
  -> 内容台账追加“草稿已回读”证据
```

## 不在第一期范围内

- 自动发表、群发通知、定时发表与最终确认弹窗；
- 公众号开放 API、旧 V1.1 网关、白名单、密钥或 Cookie 导出；
- 自动处理二维码、风控、协议或未知提示；
- 把草稿回读当成公开发表、公开链接或增长结果；
- 修改已冻结发布包的任何文件。

## 验收

### 自动测试

- V1.2 包导入：正确包、哈希不符、路径越界、缺失封面/正文图、错误状态、重复文章；
- 队列：原子读取、同一文章幂等、失败不盲重试、回执哈希不符拒绝；
- 草稿执行器：账号/字段/唯一保存控件/草稿列表回读的成功与失败合同；
- 内容侧回执消费：只接受匹配包哈希的 `draft_readback_confirmed`，不改变发表状态；
- 受影响单元测试、集成测试和一键发完整离屏 UI 测试。

### 真实验收

1. 大帅在一键发中确认硅基进化账号已登录；
2. 使用下一篇正常的、已冻结但尚未发表的内容包；
3. 一键发保存一篇草稿，并在草稿列表回读同标题、封面和本次时间；
4. 内容台账只出现草稿回读证据，不出现发表成功；
5. 大帅在后台打开草稿确认内容；如不满意，可在后台删除草稿，系统不自动重试；
6. 通过一次真实草稿闭环后，才另行设计自动发表。

## 实施归属

本功能修改 `publish_service`、发布页、账号路由和本地任务/回执等共享核心，只能在 `integration/oneclick-0.5.0` 集成线实施。内容项目只修改发布包交接和回执登记，保持账号、凭据与平台执行逻辑隔离。
