# 视频号单账号批量视频发布首版设计

日期：2026-09-12
状态：可审阅设计，尚未实施或执行真实平台动作。

## 已确定范围

发布中心新增“单平台批量”入口。首版固定视频号、一次一个账号、多条不同视频；任务结构预留平台与账号字段。内容采用通用标题、正文、话题与逐字段覆盖。保留现有单条多平台、抖音带货和图文矩阵流程。

## 当前源码依据

- `uploader/tencent_uploader/main.py` 已实现视频上传、描述、短标题、封面、合集、声明与定时时间回读，并接受外部页面和上下文。
- `click_publish` 当前最多循环六次点击发表，以作品列表跳转判断成功；需改为单次最终动作和严格回执，不能直接用于批量重试。
- `add_title_tags` 当前只检查文字存在，不能作为官方话题实体已写入的证据。
- `myUtils/postVideo.py` 的旧多文件循环共享内容；显式 scheduleTime 被复制给每个文件，且旧视频号函数未独立传入 description，不能作为新逐条合同入口。
- 现有任务、授权、图文矩阵串行执行可作为复用参考。批次调用同一视频号适配器，不复制平台选择器。
- 本轮未访问视频号平台；源码能力不等于当前页面或账号已验收。

## 界面与操作

内容准备：选择一个视频号账号，从素材管理或本机加入视频，支持全选、取消全选、移除、排序。建议首版每批 1–20 条，这是产品范围而非平台限额。保存、恢复和清空仅作用于当前批次；清空不删除素材文件。

内容设置：左侧视频列表，中间当前视频详情，右侧通用内容与排期。标题映射视频号短标题，正文映射视频描述；超限明确提示，不静默截断。封面逐条设置，平台要求的比例在详情中显示。

覆盖规则：每个字段独立记录继承或覆盖；缺少 override 表示继承，显式空正文/空话题表示用户清空，随后按平台必填规则校验。修改通用内容只更新继承项。“恢复通用”移除覆盖。标题、正文、话题分别保存，不能把正文中的普通 #/@ 当作有效平台实体。

检查与提交：列出每条最终文案、封面、具体排期和问题，批量确认一次后执行。编辑界面保存草稿，提交时生成不可变快照；运行中的快照不随表单变化。

## 排期

支持顺序立即发布、起始时间加间隔、每天固定时段，并允许逐条覆盖。保存明确 Asia/Shanghai 时间，确认页显示绝对日期与时间。排序变化后重新生成未覆盖排期并提示变化。

首版仅使用平台原生定时，不添加关机仍可运行的本地常驻调度。超出平台允许窗口、账号没有入口或时间回读不符时阻止该项；不得静默改成立即发布。每日固定时段只是生成绝对时间的工具，不能突破平台排期窗口。平台定时受理与实际公开分开显示。

## 执行与授权

UI 与 CLI 使用同一批次服务。准备与本地检查不打开平台；用户确认精确账号、素材、内容和排期后消费一次短期授权，启动持久化批次。一次性凭证用于启动，不要求运行期间每条重新确认。批次启动后新增内容不继承旧授权。

按账号串行处理，复用本批受控浏览器与账号上下文，每条创建干净编辑页并关闭前一条页面。批次结束释放会话。需要扫码或验证时暂停并提示，完成后续跑同一项。

每条最终动作最多执行一次。最终动作意图在点击前持久化；点击后中断但无法确认是否实际提交时，保守进入结果不明并只读核对。仅页面跳转、按钮消失或返回无异常不算成功。

单条素材/字段明确失败可继续下一条；账号失效、风控或验证问题暂停批次；提交结果不明也暂停，先核对再继续。暂停在安全边界生效，取消只取消未执行项，已在平台受理的定时内容保持原状态并明确提示。

重启恢复先检查租约与最后阶段；已成功项永不重放，结果不明项仅允许只读核对。明确失败项的重试生成独立子批次和新确认，保留原记录。重新排期也需生成新的确认快照。

## 数据与模块

批次包含 schemaVersion、workflow、platform、accountId、defaults、items、schedulePolicy、snapshotHash。每项包含稳定 itemId、素材路径及哈希、排序、逐字段覆盖、解析后的最终内容、封面哈希、绝对排期和发布指纹。身份不依赖列表下标。去重同时核对成功与结果不明记录；改变排序或批次名不能规避保护。

建议新增 `video_batch_contract.py`、`video_batch_service.py`、`video_batch_executor.py`、`video_batch_draft_service.py` 和独立批量页面；通过 publish_service、task_service、CLI 和发布中心接线。数据库迁移沿用现有任务机制，保留逐条阶段、错误码、平台 ID/链接、排期回执及授权关联。平台交互仍归视频号适配器。

CLI 提供 batch-check、batch-authorize、batch-start 和任务查询，稳定返回 batch/task ID、逐条 itemId、阶段、状态、错误码、错误说明和回执。只接收本地内容清单和账号 ID，不接收凭据。默认本地检查；正式执行必须持有确认快照对应授权。

## 验收与实施顺序

1. 建立字段覆盖、素材身份、排期与不可变快照测试；完成本地草稿和队列状态。
2. 修复视频号一次提交、短标题/正文独立传递、官方话题实体及明确平台回执；用模拟页面覆盖失败、中断、重复提交保护。
3. 接通 UI、CLI 和逐条结果；验证同一输入一致、进程退出可恢复、旧发布流程不回归。
4. 使用当前测试账号单条受控预检，回读实际封面、字段和定时入口；记录当前能力。真实预检材料和动作应按当次授权确定。
5. 取得具体内容发布授权后做两条小批次验收，逐条取得平台 ID 或唯一结果证据，并验证立即/定时状态不混淆。

设计通过后补充项目要求的架构/状态图并落实实施计划。全量测试遵守现有项目质量门；真实发布独立取证。当前设计不构成任何公开发布授权。
