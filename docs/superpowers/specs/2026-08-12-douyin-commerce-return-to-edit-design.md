# 抖音带货提交后返回修改设计

## 背景

抖音带货进入“检查与提交”后，批量执行期间会禁用普通返回。执行结束或手动暂停后，平台设置代际已经关闭，现有按钮会变为“开始新内容”，不能保留失败、暂停或未开始的视频返回前两步修改。

本设计增加受控的“返回修改未完成视频”能力。它不回滚平台提交，不改写原任务，也不把状态不明确的视频重新提交。

## 目标

- 全部失败时，可把全部失败视频带回修改。
- 手动暂停或部分失败时，只恢复失败、暂停和未开始的视频。
- 返回后默认进入“平台设置”，并可继续返回“内容准备”。
- 允许修改视频、标题、文案、标签、音乐、声明、地点、返佣筛选和排期。
- 已成功视频不得进入修改批次，原任务及逐条回执保持不变。
- 修改后再次提交时创建新任务，并记录来源任务号。

## 非目标

- 不回滚、删除或修改已经取得平台成功回执的视频。
- 不把“平台状态待核对”解释为失败。
- 不恢复登录失效、验证码处理中、未知安全暂停或仍在运行的任务。
- 不在返回修改时访问抖音、上传视频、保存平台草稿或提交发布。
- 不复用旧任务继续写入新的执行结果。

## 交互设计

### 检查与提交页

批量运行期间保持当前约束，禁止用户返回编辑，避免发布线程和界面同时修改批次数据。

按钮状态如下：

| 状态 | 可见操作 |
| --- | --- |
| 正在执行 | `暂停发布` |
| 已请求手动暂停 | `将在当前视频后暂停` |
| 已停止且存在可修改条目 | `返回修改未完成视频` |
| 全部成功 | `开始新内容` |
| 存在待核对条目 | 禁用返回修改，并提示先确认平台状态 |

点击“返回修改未完成视频”后：

1. 重新读取原任务与逐条状态，不使用界面缓存的旧统计。
2. 完成当前临时会话与采集器关闭屏障。
3. 创建仅驻留于本地界面的修改批次。
4. 默认进入“平台设置”。
5. 用户可点击“返回内容”继续修改内容准备信息。

### 逐条结果展示

- `已成功`：锁定，不进入修改批次。
- `失败`：进入修改批次。
- `未开始／手动暂停`：进入修改批次。
- `平台状态待核对`：锁定，不进入修改批次。

原任务结果表继续保留，返回修改不会覆盖或删除原记录。

## 资格与状态规则

只有以下来源任务可以创建修改批次：

1. 已结束且全部失败或部分失败的任务；
2. `pauseReasonCode=user_request` 的手动暂停任务。

可复制的逐条状态为：

- `failed`；
- `pending`。

不可复制的状态包括：

- `success`；
- `running`；
- 平台最终回执不明确；
- 等待登录或验证码处理；
- 非用户请求导致的安全暂停。

资格判断必须在用户点击按钮时重新查询任务存储。任务仍在运行、状态已变化或来源关系不完整时，停止恢复并显示固定说明。

## 数据模型与追溯

新增“修改来源任务”公开关系，名称使用 `revisionSourceTaskId`，不复用“继续发布”的 `resumeSourceTaskId` 语义。

修改批次初始数据来自原任务中符合资格的逐条载荷：

- 共享标题、文案、标签、音乐和声明；
- 每条视频路径、地点、返佣筛选、观测佣型和排期；
- 来源任务号与来源条目号。

进入修改界面时尚未创建新的发布任务。用户再次确认提交后，才创建新的发布任务，并在任务明细显示“修改自 Txxxx”。

原任务、原任务条目、成功回执、失败原因和完成时间均不可变。

## 防止重复发布

修改批次创建时，记录来源任务中所有已成功视频的稳定媒体身份。优先使用本机素材记录 `mediaId`；旧数据缺少 `mediaId` 时，使用规范化后的 `mediaPath`。内容准备页不得把这些视频重新加入本修改批次。

即使用户通过素材选择器再次选择相同文件，也必须依据媒体身份拒绝，而不是比较显示名称。

待核对条目不得进入修改批次，因为平台可能已经接受提交。用户需先在任务明细或平台管理页确认其最终状态。

## 生命周期与关闭屏障

返回修改前统一执行关闭流程：

1. 批量 worker 已结束；
2. 当前验证码请求已清理；
3. setup generation 和 collector 已关闭；
4. 临时发布会话已关闭；
5. 回读同时满足 `closed=true` 与存活数量为严格整数 `0`。

任一条件未满足时：

- 保持在检查页；
- 保留结果表和原任务号；
- 不创建或覆盖修改批次；
- 显示固定的关闭未完成说明，不透传底层异常原文。

## 错误处理

- 来源任务不存在或状态变化：提示“原任务状态已变化，请刷新任务明细后重试”。
- 没有可修改条目：提示“当前任务没有可返回修改的视频”。
- 含待核对条目：整次返回修改保持禁用，提示用户先确认平台状态；不得只排除待核对条目后提交其余视频。
- 成功视频被重新选择：提示“该视频已在原任务中发布成功，不能加入修改批次”。
- 恢复载荷损坏或缺少必要字段：停止恢复，不修改任何界面状态。
- 新任务创建失败：修改批次仍保留在界面，允许用户修正或重试；不得回写原任务。

## 组件边界

### 任务服务

负责：

- 重新读取来源任务和条目；
- 判断任务级与条目级资格；
- 生成只含公开、可编辑字段的修改批次快照；
- 校验成功视频媒体身份禁止列表；
- 新任务提交时记录 `revisionSourceTaskId`。

任务服务不负责 Qt 控件切换，也不启动浏览器。

### 抖音带货页面

负责：

- 根据真实任务状态投影按钮文案和可用性；
- 发起关闭屏障；
- 在关闭成功后载入修改批次并切换页面；
- 阻止成功视频重新进入；
- 展示固定、可理解的错误说明。

页面不直接修改来源任务数据库记录。

### 批量执行器

保持现有职责：串行处理批次、响应显式用户暂停并写入逐条结果。本功能不允许执行器把旧任务改回可编辑状态。

## 验收测试

测试按“单项失败复现 → 单项修复 → 相关模块一次 → 收尾全量一次”的顺序执行。

必须覆盖：

1. 20 条全部失败，返回后仍为 20 条。
2. 1 条成功、19 条手动暂停，返回后只有 19 条。
3. 部分成功、部分失败、部分未开始，只恢复未成功项。
4. 已成功视频即使手动重新选择，也会被阻止。
5. 待核对、登录失效、验证码处理中和系统安全暂停不能被误恢复。
6. 返回后可以修改内容与全部平台设置字段。
7. 再次提交创建新任务并记录来源，原任务数据逐字段保持不变。
8. 关闭屏障失败时不跳页、不丢当前结果、不创建修改批次。
9. 运行中的 worker 不能与返回修改并发。
10. 全部成功时不显示“返回修改未完成视频”。

所有自动化验收均为离线测试，不访问真实账号、浏览器或抖音平台，不构成发布成功证据。

## 完成标准

- 用户可从全部失败或手动暂停结果安全返回修改未完成视频。
- 已成功和待核对视频不会进入修改批次。
- 原任务不可变，新任务来源可追溯。
- 返回修改和客户端关闭共享严格零存活屏障。
- 相关专项测试与最后一次全量回归通过。
