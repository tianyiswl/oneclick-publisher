# 一键发抖音数据监测 V2 设计

## 1. 问题与目标

当前数据监测页只展示一组账号指标。程序向抖音数据概览接口请求最近 30 天，但只保存每个指标趋势的最后一个日期点。因此页面上的“播放 532”实际是账号级最后一个可用自然日的新增播放，不是单作品累计播放，也不是近 30 天累计播放。界面未显示对象、统计日期和更新时间，造成指标含义不明。

V2 的目标是把现有只读会话采集底座升级为可用的账号运营数据页：

1. 每个数字明确统计对象、时间区间、新增/累计口径、观察时间和数据来源。
2. 支持昨日、近 7 天和近 30 天账号趋势。
3. 展示作品列表与可验证的作品级指标。
4. 平台未返回的完播率、流量来源等显示为“暂未取得”，不推算、不补零。

## 2. 范围边界

V2 只读取用户本人已在一键发登录的抖音账号数据。继续使用“官方会话直连优先，官方页面签名响应兜底”的方式。

V2 包含：

- 账号每日播放、点赞、评论、分享、净增粉、主页访问；
- 账号粉丝总数的区间末累计值；
- 昨日、近 7 天、近 30 天的区间汇总与日趋势；
- 作品标题、封面公开地址、发布时间、作品状态、作品稳定 ID；
- 作品累计播放、点赞、评论、分享，以及平台真实返回时的收藏、下载等白名单指标；
- 同步状态、数据来源、平台观察时间和本地更新时间。

V2 不包含：

- 竞品账号采集、第三方估算播放或 GMV；
- 评论正文、私信、个人粉丝明细或其他隐私数据；
- 绕过登录、验证码、滑块、权限申请或平台风控；
- 在平台没有返回时自行计算完播率、流量来源、观众画像或电商转化；
- 后台定时采集和云端上传。

## 3. 指标语义

每个指标点必须同时携带：

- `entityType`：`account` 或 `content`；
- `entityKey`：账号本地稳定键或作品平台稳定 ID；
- `metricKey`：一键发标准指标键；
- `metricScope`：`daily_increment` 或 `lifetime_total`；
- `periodStart` 和 `periodEnd`：指标所属统计区间；
- `observedAt`：平台指标的观察时间；
- `sourceMode`：`direct_session` 或 `browser_signed`；
- `metricValue` 和 `metricUnit`。

指标卡口径：

- 播放、点赞、评论、分享、净增粉、主页访问：对所选自然日范围的 `daily_increment` 求和；
- 粉丝总数：所选区间末最后一个可用 `lifetime_total`；
- 作品表中的播放、点赞、评论、分享：当前同步时点的 `lifetime_total`；
- 任何没有明确范围的平台数值不得进入公开指标模型。

页面不用“播放”这类孤立标题，而是显示“账号区间新增播放”或“作品累计播放”。页面顶部同时显示所选日期区间、平台观察时间和本地同步时间。

## 4. 公开模型

### 4.1 MetricPoint

扩展现有不可变指标模型，增加 `metric_scope` 、`period_start` 和 `period_end`。`entity_type` 放开为 `account` 与 `content`。不允许模糊范围、非自然日日期或非有限数字。

### 4.2 ContentRecord

新增不可变作品模型，字段只包含：

- `content_id`；
- `title`；
- `cover_url`；
- `published_at`；
- `content_status`；
- `content_type`。

`content_id` 必须是平台返回的稳定作品 ID。无稳定 ID 的行不落库，不用标题或封面猜测身份。`cover_url` 只接受平台官方 HTTPS 公开地址，不下载封面。

### 4.3 CollectionBatch

同一批次包含：

- 账号日级指标；
- 作品元数据；
- 作品累计指标；
- 批次平台观察时间。

作品列表空不必然代表账号指标失败；采集结果要分开记录 `accountMetricsAvailable` 和 `contentDataAvailable`。但任一子模块不能用空数组伪装成已成功取得。

## 5. 数据库

### 5.1 扩展 platform_metric_snapshots

增加：

- `metricScope`；
- `periodStart`；
- `periodEnd`。

唯一性改为同一运行、实体、指标、口径和时间区间唯一。旧数据没有可证明的口径，不得自动标记为昨日或 30 天；保留为历史快照，V2 区间汇总查询排除它们。

### 5.2 platform_contents

| 字段 | 含义 |
| --- | --- |
| accountId | 一键发账号 ID |
| platformType | 平台类型 |
| contentId | 平台作品稳定 ID |
| title | 标题 |
| coverUrl | 官方公开封面地址 |
| publishedAt | 平台发布时间 |
| contentStatus | 受控状态 |
| contentType | video 或 image |
| firstSeenAt | 首次观察时间 |
| lastSeenAt | 最后观察时间 |

`accountId + platformType + contentId` 唯一。同步时只更新白名单字段，不删除本次列表中没有返回的旧作品。

### 5.3 事务边界

一次成功同步的运行记录、账号日指标、作品元数据和作品指标必须使用同一数据库事务。任一写入失败时不留下一半更新的作品表或成功运行。

## 6. 抖音采集

### 6.1 账号日趋势

现有 dashboard 直连响应中的每个 `trends` 数组全部规范化，不再只取最后一项。只接受可解析为北京时间自然日的日期与有限数字。

对官方签名页返回的 `option_list` 采用同一规则。`current_count` 只在平台字段能明确证明是累计值时进入 `lifetime_total`；不能证明时忽略。

### 6.2 作品列表与作品数据

采集器只接收固定抖音创作者官方域名和白名单响应路径。作品列表必须分页读取，每页使用平台返回的受控游标，单次同步最多 20 页、500 个作品。达到上限时记录 `content_list_truncated`，不伪装成已穷尽。

只规范化平台明确返回的字段。请求作品详情时严格使用列表返回的作品 ID，不使用标题、封面或发布时间模糊匹配。

作品子模块失败时：

- 账号趋势已完整取得：允许保存账号数据，同步运行标记为 `partial_success` 和固定作品错误码；
- 账号趋势也失败：整次同步失败，不写任何新指标。

### 6.3 不可接受的实现

- 抓取 DOM 文字作为指标；
- 在页面中重放 fetch 或自行组合签名；
- 保存完整 JSON 响应；
- 将网络异常、URL、Cookie 或响应原文传给 UI；
- 在无作品权限时将空列表当作账号没发过视频。

## 7. 查询服务

`platform_data_service` 新增三个白名单查询：

1. `account_period_summary(account_id, days)`：`days` 只允许 1、7、30，返回日期区间、区间新增汇总、区间末累计指标、各指标的完整/部分/缺失状态。
2. `account_daily_trends(account_id, days)`：返回按日期升序的稀疏趋势，缺失日不补 0。
3. `account_contents(account_id, limit, offset)`：只返回作品元数据和最新累计指标，`limit` 最大 100。

查询输出只包含公开业务字段。不返回原始字段名、Cookie 文件、平台响应、SQL 异常或内部路径。

## 8. 界面

### 8.1 页头

- 账号选择；
- 时间范围：昨日、近 7 天、近 30 天，默认近 7 天；
- 同步数据；
- 数据来源、平台观察时间、本地同步时间。

### 8.2 账号指标卡

卡片标题包含口径：

- 账号区间新增播放；
- 账号区间新增点赞；
- 账号区间新增评论；
- 账号区间新增分享；
- 账号区间净增粉；
- 账号区间主页访问；
- 账号区间末粉丝总数。

卡片下方显示“完整数据”、“部分日期”或“暂未取得”。不将部分区间和完整区间用同一个无标记数字展示。

### 8.3 趋势区

使用 Qt 绘制的轻量趋势图，不新增网络图表依赖。可在播放、互动和净增粉三组之间切换。日期缺失时断线，不用 0 连线。

### 8.4 作品表

列为：作品、发布时间、状态、累计播放、累计点赞、累计评论、累计分享。缺失字段显示“—”。默认按发布时间降序，分页每页 50 条。

作品详情页不在 V2 首轮建设；本轮只保留作品稳定 ID 和日指标扩展能力。

## 9. 状态与错误

同步状态增加 `partial_success`。公开错误码新增：

- `account_trends_unavailable`；
- `content_list_unavailable`；
- `content_list_truncated`；
- `content_payload_invalid`。

界面显示固定文案。原始异常、响应、URL 查询串和账号路径不进入 UI、数据库或任务日志。

`partial_success` 不能显示为“全部同步成功”。页面需明确说明已更新账号趋势，但作品数据未取得。

## 10. 同步与退出生命周期

同一账号仍只允许一个同步任务。时间范围只改变本地查询，不会每次切换都访问平台。

用户点击“同步数据”时，一次后台任务同步账号趋势和作品数据。页面进度只显示固定阶段：会话直连、官方签名读取、账号趋势、作品列表、作品指标、本地保存、完成。

关闭客户端时继续执行现有 5 秒收束屏障。未收束的采集任务不得被全局浏览器关闭越过。

## 11. 测试与验收

必须按 TDD 阶梯实施：

1. 模型与迁移：旧快照不伪造日期口径，新日指标与作品表原子落库。
2. 账号趋势：30 个有效日期点全部保留，无效日期、布尔值、数字字符串和重复日期固定失败。
3. 作品列表：分页、稳定 ID、受控字段、截断状态和空列表语义。
4. 查询：1/7/30 天汇总、区间末累计、稀疏日期、部分数据标记和作品分页。
5. UI：时间切换零网络、口径文案、趋势断线、作品表、部分成功、重复同步和退出屏障。
6. 受影响模块测试。
7. 收尾时唯一一次全量测试。

真实运行验收：

- 同一账号同步后，页面明确显示账号区间、平台数据日期和本地同步时间；
- “昨日”播放值与官方后台同日账号概览一致；
- 至少一条作品的标题、发布时间、播放、点赞、评论和分享与官方作品页一致；
- 缺失完播率等未授权字段显示“暂未取得”，不显示 0；
- 同步后无残留 Chromium 或 Playwright 会话。

如果真实抖音页面未发起允许列表内的作品数据响应，本轮交付必须记为“账号趋势完成，作品数据未取得”，不得声称完整数据平台已实现。
