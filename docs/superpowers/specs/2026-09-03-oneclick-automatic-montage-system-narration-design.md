# 一键发自动混剪「系统自动配音」设计

日期：2026-09-03

状态：书面设计已获用户批准；尚未实施，不代表客户端已经支持自动配音

## 1. 目标

在现有“自动混剪”页面增加第三种声音模式“系统自动配音”。用户输入一份中文解说文案后，一键发在本机生成一条中文配音，并把这条完全相同的配音用于本批次生成的所有视频。

这一切片解决两个直接问题：

- 静音混剪缺少可直接使用的解说音轨；
- 保留素材原声会把连续讲话随机截断，无法保证一句话完整。

## 2. 已批准范围

本切片包含：

- 自动混剪页面新增“系统自动配音”声音模式；
- 新增多行“配音文案”输入框；
- macOS 使用本机系统中文声音生成音频；
- Windows 使用本机系统中文声音生成音频；
- 每个批次只合成一次配音，所有成片复用同一份音频；
- 配音实际时长决定本批次视频时长；
- 配音模式完全移除素材原声；
- 本地回执记录声音、时长和配音哈希；
- 生成后回读每条成片的音轨、时长和配音一致性。

本切片不包含：

- 云端语音服务、API Key 或付费模型；
- 声音克隆、指定人物音色、情绪和语速调节；
- 背景音乐、自动混音、自动降噪；
- 字幕生成、语音识别或口型同步；
- 自动进入发布任务或自动公开发布。

已有的 P002 专属 VoxCPM2 音色和资产不进入一键发通用功能；两者保持项目隔离。

## 3. 用户界面

### 3.1 声音模式

“声音”下拉框保留现有两项并新增一项：

1. 静音；
2. 保留环境原声（仅无人声素材）；
3. 系统自动配音。

选择“系统自动配音”后：

- 显示“配音文案”多行输入框；
- 隐藏“我确认所选素材不含连续讲话”；
- “每条总时长”不可编辑，并显示“跟随配音”；
- “每个镜头”仍可编辑；
- 页面提示“整批视频使用同一条系统配音，素材原声会被移除”。

切回“静音”或“保留环境原声”时，原有行为不变。切换模式不主动清空用户已输入的配音文案，避免误操作丢失内容；只有当前模式为“系统自动配音”时文案才参与生成。

### 3.2 结果反馈

生成进度新增两个可见阶段：

- 正在生成系统配音；
- 正在读取配音时长。

成功后页面显示本批次实际使用的系统声音名称和最终成片时长。若系统没有中文声音或音频无法回读，页面显示明确原因，不生成静音成片，也不回退成英文声音。

## 4. 音频生成合同

### 4.1 跨平台适配器

新增统一的本机配音服务，业务层只接收“中文文案”，不直接了解系统命令：

- macOS 适配器调用系统自带的 `/usr/bin/say`，先枚举已安装声音，再选择中文声音并生成 AIFF；
- Windows 适配器通过 Windows PowerShell 调用 `System.Speech.Synthesis.SpeechSynthesizer`，枚举已安装声音并生成 WAV；
- 中文声音优先级为简体中文，其次才是其他中文区域声音；同一优先级按稳定顺序选择；
- 第一版不提供音色下拉框，减少跨机器音色名称不同造成的无效配置；
- 文案通过临时 UTF-8 文件传给系统工具，不放进命令行参数或运行日志；临时文件在成功或失败后都清理。

如果运行系统不是 macOS 或 Windows，返回稳定错误，不尝试其他未验证方案。

### 4.2 一次合成、整批复用

配音必须在镜头计划之前生成，并且一个批次只执行一次系统语音合成：

1. 生成系统原始音频；
2. 使用当前完整 FFmpeg 运行时规范化为 48kHz、双声道 AAC 主音轨；
3. 回读实际讲话时长；
4. 在末尾补静音，得到本批次主音轨；
5. 保存主音轨 SHA-256；
6. 所有成片引用这一个主音轨文件。

禁止对每条视频分别调用系统配音，避免同一批次出现语速、停顿或声音不一致。

### 4.3 时长规则

系统自动配音模式不使用用户原先填写的“每条总时长”。有效成片时长按以下规则派生：

`有效成片时长 = max(5 秒, 实际讲话时长 + 0.3 秒尾部余量)`

- 主音轨用尾部静音补齐到有效成片时长；
- 镜头计划以有效成片时长为目标；
- 不截断解说，不强制提高语速；
- 有效成片时长超过 180 秒时，在渲染前失败；
- “每个镜头”仍须满足 0.5–10 秒，并且不能超过有效成片时长。

## 5. 视频渲染合同

系统自动配音模式下，素材镜头始终按静音方式渲染：

- 不映射任何素材音轨；
- 镜头合并完成后，再把批次主音轨写入成片；
- 不使用素材原声作为失败回退；
- 不为每条视频重新编码或重新生成配音内容。

每条成片只有在以下回读全部满足时才标记成功：

- 画面为 1080×1920；
- 视频时长与有效成片时长误差不超过 500ms；
- 存在音轨；
- 音轨时长与有效成片时长误差不超过 500ms；
- 音轨内容哈希与批次主音轨一致。

单条成片编码或回读失败时记录该条失败并继续下一条；成功项和失败项最终写入同一个原子批次回执，不遗留“运行中”状态。

## 6. 数据与回执

### 6.1 请求字段

在现有混剪请求中增加：

- `audio_mode = "narration"`；
- `narration_text`：用户输入的完整中文配音文案。

`narration_text` 在其他声音模式下可以为空并被忽略；在系统自动配音模式下去除首尾空白后必须非空。现有 `mute` 和 `source` 请求保持兼容。

### 6.2 批次文件

系统配音批次至少新增：

- `narration/master.m4a`：规范化并补齐后的唯一主音轨；
- `narration/receipt.json`：系统声音、区域、讲话时长、主音轨时长、文件哈希和生成状态。

最终 `batch-receipt.json` 增加：

- `narration.voice_id`；
- `narration.voice_locale`；
- `narration.speech_duration_ms`；
- `narration.master_duration_ms`；
- `narration.sha256`；
- 每条输出的 `narration_sha256` 和音轨回读结果。

配音原文保留在本地 `request.json` 供用户追溯，但不写入普通运行日志，不发送到网络。

## 7. 稳定错误码

| 错误码 | 含义 | 阶段 |
| --- | --- | --- |
| `montage_narration_text_required` | 系统配音模式没有有效文案 | 请求校验 |
| `montage_narration_platform_unsupported` | 当前操作系统没有已实现适配器 | 适配器选择 |
| `montage_narration_voice_unavailable` | 没有可用中文系统声音 | 配音前 |
| `montage_narration_synthesis_failed` | 系统语音合成失败或没有生成有效文件 | 配音生成 |
| `montage_narration_duration_invalid` | 配音时长无效或有效成片超过 180 秒 | 时长回读 |
| `montage_narration_audio_readback_failed` | 主音轨或成片音轨回读不一致 | 规范化/成片回读 |

这些失败在渲染前发生时必须直接结束批次并写失败回执，不生成看似成功的静音视频。

## 8. 代码边界

预计改动范围：

- 新增 `app_core/narration_service.py`：系统声音枚举、双平台适配、一次合成、规范化和音频回读；
- 修改 `app_core/montage_models.py`：新增声音模式、文案字段和校验；
- 修改 `app_core/montage_service.py`：把配音阶段放在镜头规划之前，持久化主音轨与回执；
- 修改 `app_core/montage_runtime.py`：静音画面渲染、主音轨复用和音轨一致性回读；
- 修改 `ui/automatic_montage_page.py`：声音模式、配音输入框、时长禁用和进度反馈；
- 新增或扩展对应单元测试、页面测试和运行时测试。

不复制第二套混剪计划器，不改变发布服务，不引入新的网络依赖。

## 9. 验收标准

### 9.1 自动化测试

- 请求模型接受 `narration`，拒绝空文案，原有 `mute/source` 测试继续通过；
- macOS 和 Windows 适配器都可通过替身运行器验证声音筛选、临时文件传参和稳定错误码；
- 同一批次生成多条视频时，系统语音合成函数只调用一次；
- 配音时长覆盖用户原目标时长，并正确驱动镜头数量和最后一个镜头长度；
- 配音模式的镜头命令不映射素材音轨；
- 三条输出都存在音轨、引用同一 `narration_sha256`，音轨内容回读一致；
- 中途单条失败时其他条继续，最终状态为部分失败；
- 页面在三种声音模式间切换时，只显示当前需要的控件且不会清空文案。

### 9.2 当前 Mac 真实验证

在源码客户端中用一段短中文文案和至少两条真实视频素材生成三条成片，确认：

- 实际调用一条已安装中文系统声音；
- 三条成片声音内容完全一致；
- 三条视频没有素材原声串入；
- 配音最后一句完整，末尾保留约 0.3 秒余量；
- 批次回执中的声音、时长和哈希与文件回读一致；
- 人工播放至少一条，确认声音可听、画面节奏可接受。

### 9.3 Windows 边界

在 Mac 上只能完成 Windows 适配器的自动化合同测试，不能据此宣称 Windows 真实配音可用。Windows 端必须在 Windows 主机上用打包客户端完成一次中文系统声音生成和三条成片回读，才算 Windows 运行验收通过。

## 10. 完成边界

- 书面设计、架构图和测试计划通过，只代表方案确定；
- 源码和自动化测试通过，代表功能实现；
- Mac 源码真实生成并人工播放通过，代表 Mac 源码可用；
- Mac/Windows 打包客户端分别在对应系统真实生成并回读通过，才代表该平台正式客户端可用；
- 本地视频生成成功不等于已经进入发布任务，更不等于公开发布。
