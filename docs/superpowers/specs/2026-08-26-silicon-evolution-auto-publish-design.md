# 硅基进化公众号一键发 CLI 自动直发设计

日期：2026-08-26
状态：大帅已确认“自动直发”；待实现与真实预检

## 目标

硅基进化每日内容通过所有本地质量门并冻结后，由一键发 CLI 自动完成公众号预检和正式提交。整个过程不要求大帅逐篇点击确认。

自动直发只适用于已明确绑定的“硅基进化”公众号。平台出现二维码、登录失效、风控、未知弹窗、字段回读不一致、账号不一致、重复文章或没有明确回执时，必须停止，不能重试、不能换账号、不能降级为浏览器或旧网关。

## 已确认边界

- V1.2 冻结包仍是内容事实的唯一来源；`release-manifest.json`、正文、封面、图片和质量回执不得被直发流程修改。
- 冻结包中的 `publish_allowed=false` 保持不变。它表示内容包自身不携带平台凭据或发表开关；自动发表权限另由一键发本机、账号绑定的自动直发档案提供。
- 不使用旧 V1.1 网关，不导出 Cookie、二维码、Token、密码或验证码。
- 自动发表不等于公开可访问或增长成功。平台提交、平台回执、公开链接和数据回收继续分别记录。
- 群发通知和平台推荐默认关闭；除非大帅另行明确授权，自动直发不会把文章以群发通知推送给关注者。

## 方案选择

不把 V1.2 冻结包伪装成通用 `oneclick-content/v1` 包，也不修改既有草稿桥的开关。

采用独立的“硅基进化直发适配器”：它只读取并复核 V1.2 包，再生成一键发执行器需要的内存载荷。这样可保留当前 HTML、900×383 封面、正文图片锚点和文件哈希，同时不放宽通用内容包的格式约束。

## 组件与数据流

```text
已冻结的 V1.2 发布包
  -> 直发交接记录（文章 ID、路径、冻结哈希；不含正文或凭据）
  -> 一键发重验所有文件哈希与质量回执
  -> 当前账号与“硅基进化”发布档案双重匹配
  -> 公众号字段预检并逐项回读
  -> 本机自动一次性授权
  -> 正式提交
  -> 后台结果回读 / 原子回执
  -> 内容台账写入提交或平台回执证据
```

### 1. 内容侧直发交接

内容项目仅在 V1.2 包完成且主状态为 `release_ready` 时写出 `silicon_evolution_auto_publish/v1` 交接记录。记录包含文章 ID、绝对包路径、`release-manifest.json` SHA-256、目标项目 ID 和创建时间。

同一 `article_id + package_sha256` 只能有一份活动交接。内容项目收到未知、失败或不匹配回执时保持未发表状态；不得自行制造第二份包或重复提交。

### 2. 一键发 V1.2 直发适配器

新增只读导入器，复用 V1.2 草稿导入器的逐文件哈希、路径安全和文章身份校验，并额外要求：

- `state=release_ready`；
- `publication.json` 与冻结包的文章 ID、标题、摘要一致；
- `quality-receipt.json` 表明质量门通过；
- 正文、封面和全部正文图都在冻结包内；
- 明确的 AI 图片声明与图片路径一致；缺失时停止，不替平台自动确认来源声明。

适配器输出仅供公众号执行器使用的不可变内存载荷；不生成可被人工改写后再次提交的临时发布包。

### 3. 本机自动直发档案

一键发为项目 `silicon-evolution` 保存一份本机档案，内容只有：项目 ID、显示名、唯一公众号账号 ID、账号显示名、`autoPublish=true` 和版本。档案不保存会话或任何凭据。

任务开始时同时验证档案账号 ID、账号类型和公众号编辑页回读的账号显示名。任一不符即失败。自动授权只针对这一条项目—账号组合、同一冻结哈希和一次已成功预检，有效期十分钟且消费后失效。

### 4. 预检、提交与回执

预检和正式提交共用同一份已校验载荷。预检必须回读标题、摘要、HTML 正文、封面、正文图、账号和可见发表控件；成功后才创建自动一次性授权。

正式提交前再次核对冻结哈希和页面字段。只允许已明确的“发表”动作；群发通知和定时发表均保持关闭。任何新增弹窗、二维码、风控、协议或页面文本变化都安全停止。

提交后读取平台明确的结果页或内容管理列表，写出原子回执。回执只记录文章 ID、包哈希、账号、阶段、时间、平台内容 ID/链接（若页面实际提供）和稳定错误码；不得写入凭据或全文。

### 5. 状态口径

内容项目新增发表证据事件，而不是把本地交付写成已发表：

| 证据 | 含义 |
| --- | --- |
| `oneclick_preflight_confirmed` | 字段已在后台编辑页回读，尚未发表。 |
| `oneclick_publish_submitted` | 已触发平台发表，尚不证明公开可访问。 |
| `oneclick_platform_receipt_confirmed` | 平台结果页或管理列表已确认目标内容。 |
| `public_link_confirmed` | 有可访问公开链接；这是可选的更高层证据。 |

失败、超时或回执不唯一不改变已有的文章发表状态。没有回执时只能保留“提交未知”，不能声明已发表。

## 测试与真实验收

### 自动测试

1. 正确 V1.2 包可生成直发载荷；哈希、路径、质量回执、AI 声明、文章身份或图片锚点任一异常均拒绝。
2. 自动直发档案只能绑定一个有效公众号账号，账号类型或显示名不符均拒绝。
3. 正式提交必须绑定同一哈希、全部成功预检和未消费的一次性授权；重复文章不可再次提交。
4. 群发通知、定时、未知弹窗、二维码、风控、账号不一致和回执不唯一均安全停止。
5. 内容侧只消费文章 ID 与冻结哈希同时匹配的回执，且不会把预检或提交误写成公开发表。

### 真实验收顺序

1. 配置唯一的硅基进化账号档案，但不建立草稿、不发表。
2. 用一篇新的正常冻结包进行一次真实预检，回读所有字段。
3. 用另一篇新的正常冻结包进行一次自动正式提交，并从平台结果页或管理列表回读。
4. 只有上述两步均成功，才将每日自动化切换为直发；当天已有包不会被补发。

## 影响范围

- 一键发集成线：V1.2 直发导入器、受控发布服务、CLI/MCP、账号档案、任务回执和测试。
- 硅基进化内容项目：冻结包中的直发必需声明、交接/回执消费者、状态事件、日常自动化配置和测试。
- 不修改旧网关、通用 `oneclick-content/v1` 解析器的既有合同，也不改变其他内容项目。
