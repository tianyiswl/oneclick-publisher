# 抖音带货批量发布工作台设计

## 目标

在“一键发”中将现有抖音带货单视频流程升级为统一的批量工作台：同一抖音账号一次处理 1 至 20 条视频，复用标题、文案、标签、配乐和作品内容声明；为每条视频分别设置官方地点与发布方式。

批量任务默认立即发布。用户可切换为“按间隔定时”，填写北京时间起始时间与间隔分钟数；系统按视频列表顺序生成时间，允许逐条覆盖具体时间。选择 1 条视频时，该工作台即为单条发布流程，不再维护另一套页面。

## 已锁定的产品规则

1. 一个批次只允许一个已登录且状态正常的抖音账号。
2. 每批 1 至 20 条本地视频；标题、文案、标签、配乐、作品内容声明对整批统一。
3. 每条视频必须选择一个官方地点预设；地点可在多条视频中复用。
4. 默认立即发布。启用定时后，必须是 Asia/Shanghai 的未来时间；可用“起始时间 + 间隔分钟”批量生成，允许单条覆盖。
5. 开始实际执行前必须展示完整批量确认清单，并由用户点击一次“开始批量发布”。
6. 平台动作只使用受控浏览器自动化，不使用官方 API、签名参数、私有接口或伪造地点数据。
7. 浏览器默认无头运行。仅在平台要求二维码、短信验证码、登录、验证码或未知风控/合规确认时，客户端才显示受控交互。

## 信息架构和界面

侧边栏保留“抖音带货”入口。进入后是三个步骤，页面不增加多余解释性文字：

1. **内容准备**：左列选择账号并显示头像、主体和账号名；中列填写共享标题、文案和标签；右列多选视频，显示视频封面缩略图、截断文件名、时长和分辨率。底部提供保存本地批次草稿、恢复已保存内容及“进入平台设置”。
2. **平台设置**：左列统一选择收藏音乐和作品内容声明；右列为逐条视频表格，每行包含视频、官方地点预设、发布方式/时间。默认立即发布；切换按间隔定时后显示起始时间和间隔，并允许单条覆盖时间。
3. **检查与提交**：显示账号、共享内容摘要、每条视频的地点和发布时间，以及本地准备状态。只有所有条目均配置完整，才显示“开始批量发布”。

实现视觉与交互基准为会话中已确认的批量工作台样稿；该样稿不是产品源码。

## 官方地点预设

### 预设的来源与本地保存

“官方地点预设”按抖音账号保存到本机。预设仅保存本次功能必要的、可见且可回读的信息：平台稳定标识（若页面提供）、名称、完整地址、地点范围（本地/国内）、账号关联和最近验证时间。

预设不是平台已写入状态。每个真正执行的视频都必须在对应抖音编辑页重新搜索并以稳定标识或完整身份精确匹配，再选择并回读。

### 受控收集

新增地点预设时，客户端通过受控抖音编辑器会话读取用户选择的官方候选。若平台需要视频才能显示地点控件，使用专门的非提交会话完成查询；不保存草稿、不发表。控件变化、候选歧义、没有可回读标识或无权限时安全停止，不创建可用预设。

## 批量执行与状态

### 本地批次状态

本地草稿保存：账号、共享内容、所选视频路径与元数据、逐条地点预设、发布方式与时间，以及各条的本地执行状态。它不等同于平台草稿、平台定时或公开发布。

每条记录至少有以下状态：`待处理`、`处理中`、`等待验证`、`已发布`、`已定时`、`失败`、`已阻断`。只有取得该平台最终回执并回读后，才写入“已发布”或“已定时”。

### 执行顺序

一个批次同时最多保持一个受控编辑器会话，按视频列表顺序串行处理：

1. 回读账号身份；
2. 上传当前视频；
3. 填写并回读标题、文案与标签；
4. 选择并回读同一首收藏音乐；
5. 选择并回读同一份作品内容声明；
6. 重新搜索、精确匹配、写入并回读该行官方地点；
7. 若该行启用定时，设置并回读准确的北京时间；
8. 最终提交；
9. 回读平台最终发布或定时回执。

账号或视频发生变更时，当前批次需要重新建立编辑器会话并重新上传受影响视频。只修改标题、文案、标签、地点、声明、配乐或定时时，不应重新上传视频；在可安全确认同一编辑器会话仍有效时，只写入变化字段并回读。

### 失败与恢复

- 单条上传、地点匹配、时间回读或最终回执失败：标记该条失败并继续处理后续条目；后续可以只重试失败条目。
- 账号会话失效、二维码、验证码、短信验证、未知合规/风控提示：整批暂停，不提交后续条目。
- 二维码只保留给用户扫码；不提取 Cookie 或凭据。
- 短信验证使用客户端原生对话框展示当前视频，等待用户输入。重发操作遵守平台 60 秒倒计时；验证码通过后在同一会话从当前条自动继续。验证码输入失败或页面状态不能可靠回读时安全停止。
- 已取得平台成功回执的条目永不自动重提。

## 数据边界

新增或扩展的本地任务载荷建议包含：

```json
{
  "workflow": "douyin-commerce-batch",
  "accountId": "本机账号标识",
  "sharedContent": {
    "title": "统一标题",
    "description": "统一文案",
    "tags": ["标签"],
    "favoriteMusicId": "平台音乐标识",
    "declaration": "声明类型"
  },
  "publishMode": "immediate|interval-schedule",
  "schedule": {
    "timezone": "Asia/Shanghai",
    "startTime": "可选",
    "intervalMinutes": "可选"
  },
  "items": [
    {
      "mediaPath": "本地视频路径",
      "locationPresetId": "本机预设标识",
      "scheduleTimeOverride": "可选",
      "status": "本地执行状态",
      "platformReadback": "仅非敏感回读结果"
    }
  ]
}
```

不得保存 Cookie、二维码、验证码、短信正文、原始网页 HTML、私有请求、账号凭据或不可公开会话数据。音乐缓存和地点预设均只保存当前账号可回读的稳定业务标识与展示信息。

## 范围外

- 多账号批量发布；
- 图文或文字批量带货；
- 自动选择具体团购商品、套餐或门店；
- 非官方地点源、第三方地图替代或私有接口；
- 绕过验证码、扫码、登录或风控；
- 将平台编辑页填写、上传或本地任务创建误记为发布成功。

## 验收与测试

### 离线测试

1. 单账号、1 至 20 条视频限制与共享字段约束；
2. 默认立即发布、间隔定时、单条时间覆盖、Asia/Shanghai 未来时间校验；
3. 地点预设按账号隔离、重复复用、精确匹配、歧义和无权限安全停止；
4. 单条失败继续、全局验证暂停、验证码 60 秒重发倒计时、恢复未完成条目；
5. 平台回读前不得记录为已发布或已定时；已成功条目不可重提；
6. 内容字段小改不触发重复上传，账号或视频变更触发受影响条目的重建。

### 客户端验收

1. 账号、共享内容、多视频、地点和时间在工作台中可直观看到；
2. 默认立即发布，切换间隔定时后自动生成每行时间且单条可编辑；
3. 每行地点已选后展示完整地址；
4. 本地批次可保存和无弹窗恢复；
5. 等待上传、查询或回读时显示进度；浏览器不无故前置；
6. 任务记录显示批量场景、逐条地点、时间、回读与失败原因。

### 真实验收顺序

1. 使用非发布预检，验证账号、逐条地点重新匹配、共享字段和时间回读；
2. 用户单独明确授权后，执行一批真实提交；
3. 遇到二维码、短信验证码、登录失效或未知提示时停在客户端交互，等待用户处理；
4. 仅以每条平台最终回执作为发布/定时成功证据。

## 设计自审

- 共享字段与逐条字段明确分离，避免一次批量配置覆盖地点与时间差异。
- 地点预设提升批量配置效率，但每条仍做平台精确匹配，避免本地缓存被误认为真实平台状态。
- 单会话串行策略牺牲并发换取可恢复性、低资源占用与验证码处理可靠性。
- “默认立即发布”与“可选间隔定时”同时满足临时批发和错峰运营。
- 执行状态严格区分本地准备、编辑页填写、平台提交与平台最终回执。
