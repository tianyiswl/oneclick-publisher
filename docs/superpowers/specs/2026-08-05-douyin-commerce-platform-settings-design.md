# 抖音带货平台设置与后台进度设计

状态：用户已确认，待实施

日期：2026-08-05
范围：一键发开发版「抖音带货」的上传后平台设置页与后台上传状态

## 目标

将上传后的平台设置从一次只显示一个大卡片的串行页面，改为紧凑、同屏可理解的双栏工作区；同时让浏览器在正常上传期间保持隐藏，并将非敏感的实际执行进度反馈到一键发客户端。

## 已锁定的用户体验

### 平台设置双栏

左栏是主操作区，包含两个卡片：

1. **配乐**：先显示“读取收藏音乐”主按钮。只有平台返回候选后才展开可滚动列表；用户选中一首后点击“使用这首音乐”，并显示已回读的歌名、作者、时长。
2. **发布定位**：提供范围选择（默认“国内”，可切换“本地”）、关键词、搜索按钮和候选列表。候选必须显示完整地址；点击候选只是暂选，必须再点击“确认选择此地点”。确认并由平台回读后，候选列表收起，替换成名称、完整地址和“更换定位”。

右栏是发布设置区，固定显示：

1. **作品声明**：用户明确选择一项，再点击“确认声明”；只在页面回读一致后标记完成。
2. **定时发布**：默认“立即发表”；开启后显示日期和时间，校验 Asia/Shanghai 的未来时间。定时不是必填项。

页面底部只保留一个主操作“检查并继续”。未完成项必须在对应卡片中给出短提示；不使用大段流程说明、重复状态或原始自动化错误。

### 上传与浏览器边界

- 正常账号校验、视频上传、平台处理和字段回读使用隐藏的受控浏览器窗口；客户端不显示浏览器。
- 浏览器保持有界面但在屏幕外运行，不改为纯无头模式，以维持已验证的抖音上传兼容性。
- 若检测到登录失效、二维码、验证码或需要重新认证：立即关闭或安全终止当前临时编辑会话，客户端只显示“登录已失效，请到账号管理重新登录”。
- 该提示只提供“前往账号管理”导航；不在抖音带货当前页打开登录窗口、不自动前置浏览器、不尝试扫码或登录。
- 账户重新登录后，用户需从内容准备重新上传；不保留平台临时会话，也不把失败任务误记为上传成功。

### 客户端进度

上传期间在内容准备页底部主操作区域显示一条紧凑的进度卡，阶段固定为：

1. 正在核对账号会话
2. 正在打开隐藏编辑会话
3. 正在上传视频
4. 正在等待平台处理
5. 正在回读标题与文案
6. 已进入平台设置

音乐、地点、声明等后续操作使用同一进度卡，只显示当前动作，例如“正在读取收藏音乐”“正在搜索国内地点”“正在确认作品声明”。进度只含阶段与结果，不含 Cookie、二维码、DOM、请求参数、选择器或账号凭据。

## 信息架构

```text
上传完成
  └─ 平台设置
      ├─ 左栏：配乐与发布定位
      │   ├─ 配乐：读取 → 选中 → 回读
      │   └─ 地点：范围/搜索 → 暂选 → 确认并回读
      ├─ 右栏：作品声明与定时发布
      │   ├─ 声明：选择 → 确认并回读
      │   └─ 定时：立即发表 / 未来北京时间
      └─ 底部：检查并继续
```

音乐、地点、声明仍按平台真实依赖关系受控：未完成音乐时地点按钮不可用，未完成地点时声明不可确认；右栏不隐藏，而是以简短禁用说明表达前置条件。定时可独立填写，但“检查并继续”只有音乐、地点、声明与定时校验均满足时启用。

## 技术方案

### 进度事件

新增仅存在内存中的 `CommerceProgressEvent`（或同义数据结构），字段为：

- `phase`：固定阶段标识，例如 `checking_session`、`uploading_video`。
- `label`：用户可见的短中文状态。
- `state`：`running`、`succeeded`、`failed`、`needs_login`。

`DouyinCommerceSessionManager.start_upload()` 接受可选的进度回调；它在专用 asyncio 会话线程中发出阶段事件。`BackgroundTaskRunner` 新增 Qt `progressed` 信号并安全转发到 GUI 线程，`DouyinCommercePage` 只更新进度卡，不从回调中读写平台页面。

### 隐藏浏览器与登录失效

带货上传明确使用“隐藏的有界面窗口”模式，保留现有 `--window-position=-32000,-32000` 机制，并禁止上传路径调用任何前置窗口的辅助函数。登录识别必须转化为受控的 `DouyinCommerceLoginRequiredError`（或同义错误码），而非将原始超时和选择器异常直接投给 UI。

页面接到该错误后：清空 `_session_id`，保留本地已保存内容，显示短提示与“前往账号管理”按钮；不启动登录、不开浏览器、不重试上传。

### 双栏渲染

保留 `DouyinCommercePage` 与已有 `QStackedWidget` 页面结构，不重写业务会话。平台页由新的 `platform_left_column` 与 `platform_right_column` 组成：左侧承载音乐和地点卡，右侧承载声明和定时卡。删除 `platform_stage_stack` 对正常页的单卡片占位职责，或仅将其保留为内部状态兼容层。

未加载的音乐列表和地点候选列表默认不占高度；状态、错误和回读结果在对应小卡中原位显示。

## 数据与安全边界

- 本地草稿仅保存账号引用、视频引用、标题、文案、标签和更新时间。
- 不保存浏览器会话、Cookie、二维码、验证码、平台原始请求、DOM 或凭据。
- 本轮不改变最终预检、保存草稿、定时提交或公开发布逻辑。
- 上传完成、字段回读、预检通过、平台定时提交和公开发布仍是不同状态；前一状态不得推断后一状态。

## 验收标准

1. 上传后的平台设置同屏显示左侧配乐/地点与右侧声明/定时，且不存在未加载音乐造成的大块空白。
2. 音乐、地点和声明必须通过用户确认和平台回读；地点确认后显示完整地址卡。
3. 正常上传时浏览器不出现在前台，客户端能依次显示上传进度。
4. 登录失效时客户端只提示前往账号管理重新登录，不在当前页打开或前置浏览器。
5. `检查并继续` 仅在音乐、地点、声明及可选定时均满足条件时启用。
6. 离线单元/UI 测试覆盖双栏可见性、懒加载区域、进度事件、登录失效安全停止和不泄露原始自动化错误。
7. 开发版仅用模拟会话验收上述 UI；本轮不执行真实抖音上传、草稿、预检或发布。
