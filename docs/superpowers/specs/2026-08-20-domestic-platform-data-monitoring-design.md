# 一键发国内平台数据监测扩展设计

## 1. 目标与范围

本轮在现有抖音数据监测 V2 基础上，依次接入：

1. 小红书；
2. 视频号；
3. 快手；
4. B站；
5. 公众号。

每个平台必须同时具备账号趋势、作品列表和单作品累计指标，才可标记为“完整”。任一层未取得时只能显示“部分取得”或“未取得”，不能用空数组或零值冒充成功。

平台按上述顺序串行实施和真实验收。前一个平台未达到真实只读运行闭环前，不并行进入下一个平台的正式实现。

本轮不包含：

- TikTok、YouTube、Instagram Reels、Facebook Reels；
- 评论全文、私信、收入、订单或其他隐私与交易数据；
- 绕过验证码、滑块、风控或平台权限；
- 自建签名服务、逆向通用签名算法或长期常驻浏览器；
- 云端上传账号数据或 Cookie；
- 用离线测试结果替代真实账号验收。

## 2. 采集路线

每个平台使用同一两阶段路线。

### 2.1 会话直连优先

适配器读取一键发账号管理已经保存的本地登录会话，只访问代码白名单内的官方只读接口。请求必须同时校验 HTTP 状态、平台业务状态、实体身份、统计周期和指标结构。HTTP 200、外层成功码、空数组或页面可见都不能单独证明数据可信。

### 2.2 官方页面签名兜底

只有直连明确因动态签名或当前页面上下文不可用时，才启动短生命周期无头浏览器。浏览器使用独立临时上下文，打开官方创作者后台，只监听页面自身产生的白名单 JSON 响应；不得注入重放请求、点击写操作或绕过验证。取得可信响应或确认失败后，必须严格关闭页面、上下文、浏览器和 Playwright。

登录失效返回 `login_required`；出现验证码、滑块或安全验证返回 `verification_required`，交还账号管理，不自动处理。

## 3. 组件与边界

复用现有 `platform_data_models.py`、`platform_data_service.py`、`platform_data_sync.py`、数据库表和 `DataMonitorPage`，新增五个互相隔离的适配器：

- `xiaohongshu_data_collector.py`；
- `wechat_channels_data_collector.py`；
- `kuaishou_data_collector.py`；
- `bilibili_data_collector.py`；
- `wechat_official_data_collector.py`。

`platform_data_collectors.py` 只负责按平台类型选择适配器，不包含平台解析逻辑。每个适配器只了解本平台白名单端点、业务状态、分页规则和字段映射，对外统一返回 `CollectionBatch` 或固定 `CollectionFailure`。

每个平台的实施分为两个明确阶段：

1. 使用真实已登录账号做一次只读探测，确认官方后台实际请求、统计周期和字段含义；
2. 把确认后的请求和字段固化为白名单适配器，并用同一真实账号完成只读同步回读。

探测结果不得把 Cookie、Token、响应原文、HTML、DOM、查询签名或账号隐私写入设计、测试、日志和数据库。

## 4. 数据模型与指标口径

每批数据由三层组成：

### 4.1 账号层

- 区间播放或阅读；
- 区间点赞、评论、分享、收藏；
- 区间末粉丝总数；
- 区间净增粉；
- 区间主页或空间访问。

只有平台语义与统计范围完全一致时，才映射到统一指标键。平台不提供或无法确认含义的字段保持缺失。

### 4.2 作品列表层

- 平台稳定作品 ID；
- 标题或受控摘要；
- 发布时间；
- 作品状态；
- 经 HTTPS 官方域名白名单验证的封面地址。

作品列表必须处理分页、重复 ID、迟到页、截断和删除／隐藏作品。列表不完整时标为 `partial`，不能宣称完整。

### 4.3 单作品累计层

- 累计播放或阅读；
- 累计点赞；
- 累计评论；
- 累计分享；
- 累计收藏；
- 平台专属累计指标。

平台专属指标不强行归并。例如 B站的投币和弹幕分别保留为独立指标，不能塞进点赞或评论。

每个指标必须保留实体类型、实体键、统计周期、平台观察时间、本地同步时间和来源模式。缺失指标不创建零值快照。

## 5. 完整度与状态

每个平台、账号和同步批次分别记录：

- `accountAvailability`：`available`、`partial`、`unavailable`；
- `contentListAvailability`：`available`、`partial`、`unavailable`；
- `contentLifetimeAvailability`：`available`、`partial`、`unavailable`。

只有三层均为 `available`，且批次内数据满足模型不变量，状态才是 `success`。任一层可信但不完整时状态为 `partial_success`；三层均无可信数据时为 `failed`。

同步失败不得清空上一次可信快照。页面同时展示旧可信数据的观察时间和本次失败状态，不能把旧数据说成本次同步结果。

## 6. 同步状态机与生命周期

统一状态机为：

`排队 → 会话直连 → 必要时浏览器签名兜底 → 数据校验 → 原子保存 → 页面回读`

约束如下：

- 同一账号同一时间只允许一个同步任务；
- 直连成功后不得启动浏览器；
- 后台回调必须校验账号、平台、任务实例和当前页面代际；
- 迟到回调不得覆盖新账号、新平台或新时间范围；
- 客户端退出时先取消未启动任务，再有界等待运行任务；
- 浏览器资源关闭不完整时拒绝继续退出；
- 新同步开始前不清除旧可信页面数据，只更新运行状态。

账号层成功、作品层失败时，可信账号数据可原子保存为 `partial_success`，同时明确记录作品层失败码。不存在“整体成功但作品为空”的状态。

## 7. 数据监测页面

保留现有 V2 页面结构，新增平台维度和三层完整度。

顶部包含：

- 平台选择；
- 账号选择；
- 昨日、近 7 天、近 30 天；
- 同步按钮和固定阶段进度。

账号区包含指标卡、趋势图、统计区间、数据来源、平台观察时间和本地同步时间。

作品区包含作品列表、发布时间、状态、累计指标和分页。平台专属列随平台切换，例如 B站显示投币和弹幕；其他平台不显示无意义空列。

页面固定显示三层完整度：

- 账号数据：完整／部分／未取得；
- 作品列表：完整／部分／未取得；
- 作品指标：完整／部分／未取得。

同步结果必须具体说明缺失层，不再用笼统“同步成功”掩盖作品数据不可用。

## 8. 错误与安全边界

所有平台共用固定公开错误语义，并允许平台适配器增加受控子码：

- `collector_not_available`；
- `session_state_missing`；
- `login_required`；
- `verification_required`；
- `direct_request_rejected`；
- `browser_signature_timeout`；
- `browser_cleanup_incomplete`；
- `account_metrics_unavailable`；
- `content_list_unavailable`；
- `content_metrics_unavailable`；
- `metric_payload_invalid`；
- `metric_payload_empty`；
- `sync_persist_failed`。

日志、任务记录和 UI 只接收平台、账号本地数字 ID、阶段、固定错误码、耗时、作品数量和指标数量。异常原文、URL 查询串、Cookie 文件路径、响应体、HTML、DOM、Token 和平台内部身份不离开适配器。

数据库写入账号、作品、指标、可用性和同步终态必须在同一事务内完成。解析、验证或写入失败不得留下 `success` 运行。

## 9. 测试与验收

每个平台按同一测试阶梯执行：

1. 适配器单测：业务状态、分页、重复作品、畸形字段、登录失效、风控和清理；
2. 服务与数据库：三层可用性、原子写入、历史保留、账号隔离和时间范围；
3. Qt 页面：平台切换、缺失值、专属指标、迟到回调、重复同步和退出屏障；
4. 受影响模块测试；
5. 阶段收尾时全量测试；
6. 真实已登录账号只读同步并在数据监测页回读。

单个平台的完成证据必须同时包含：

- 提交 SHA；
- 相关与全量测试结果；
- 真实账号、真实平台和同步时间；
- 账号区间数据回读；
- 作品列表回读；
- 至少一条作品累计指标回读；
- 浏览器兜底若启动，退出后资源为零；
- 明确说明未验证或平台未提供的字段。

离线测试、HTTP 200、页面打开、空列表、历史快照和 `partial_success` 均不能单独证明该平台完整完成。

## 10. 实施顺序与停点

实施顺序固定为：

`小红书 → 视频号 → 快手 → B站 → 公众号`

每个平台独立经历：只读探测、书面端点与字段白名单、适配器实现、离线验证、真实同步验收和复审。真实账号不可用、登录验证无法完成或官方后台不提供三层数据时，该平台停在 `partial_success`，记录缺口并由用户决定是否继续投入；不得降低完整标准后宣称完成。
