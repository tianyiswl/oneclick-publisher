# 小红书数据监测适配器设计

**日期：** 2026-08-20  
**状态：** 用户已确认，待实施计划
**范围：** 一键发桌面客户端的小红书账号数据同步与数据监测展示

## 1. 背景与问题

当前数据监测页仅显示抖音账号，原因不是小红书账号未登录，而是两处生产限制：

- 页面只加载平台类型 3（抖音）的账号。
- 采集器注册表只有 `DouyinDataCollector`，小红书账号会固定返回 `collector_not_available`。

现有小红书合同验证器已在用户明确授权的一次真实只读探测中，取得账号概览、10 条作品列表和作品详情三类官方响应；资源关闭回读为 0。当前缺口已从“未知真实合同”变为“验证器尚未接入客户端正式采集器与数据监测页”。

## 2. 目标

1. 数据监测顶部拆为“平台”和“主体”两个下拉框；先选平台，再只显示该平台下的账号主体。
2. 小红书使用自己的采集器，不复用、猜测或映射抖音数据。
3. 使用已保存的小红书登录态，在短生命周期浏览器会话内被动观察官方响应。
4. 把已证实的指标转换为现有 `CollectionBatch` / `MetricPoint` / `ContentRecord` 模型，原子写入现有数据库。
5. 未观察、未提供或无法验证的指标显示为——，不写成 0。
6. 每次同步结束后必须证明浏览器资源存活数为 0；无法严格关闭时同步不得冒充成功。

## 3. 非目标

- 不导出、拷贝、显示或持久化 Cookie、令牌、签名参数或完整响应体。
- 不在客户端外重放小红书签名请求，不实现裸 Cookie HTTP 采集。
- 不使用 DOM 文本爬取作为生产数据源。
- 不点击发布、上传、编辑、删除或其他平台写操作。
- 不将本轮范围扩大到微信视频号、快手、B 站等其他平台。
- 不声称首期已取得全部历史作品；覆盖范围必须根据真实分页回读明示。

## 4. 方案选择

### 4.1 采用：短会话被动响应观察

每次小红书同步时，从账号管理保存的本地会话状态启动独立、短生命周的 Playwright 会话，只导航到 `creator.xiaohongshu.com` 官方数据页。采集器只监听由页面自然发起的响应，对已经验证的端点与响应外形做转换。

这条路线保留了浏览器内的动态签名和风控上下文，同时将浏览器成本限定为用户点击“同步数据”后的单次短会话。

### 4.2 不采用：裸 Cookie 请求

小红书官方请求除 Cookie 外还可能依赖页面生成的签名、设备上下文和风控状态。把 Cookie 复制到独立 HTTP 客户端虽然看似轻量，但实际已出现 406 / 拒绝类证据，并且增加凭据泄露风险。因此它不进入生产备选。

### 4.3 不采用：DOM 爬取兜底

DOM 文案会受页面布局、虚拟列表、格式化数值和 A/B 版本影响，无法提供稳定的字段身份与时间口径。页面可以用于导航和人工验收，不作为指标值来源。

## 5. 真实合同升级门槛

生产适配器只能使用通过以下门槛的合同：

1. 响应来自 HTTPS 且主机名严格属于小红书创作服务平台白名单。
2. URL 只保留规范化路径，不记录 query、fragment、header 或 body。
3. 响应顶层及必需嵌套节点的类型、键名和必需值类型在真实已登录账号上取得证据。
4. 账号级、作品列表、作品详情三类合同分别验证，不因其中一类出现就推定其他类。
5. 对同一账号的实际页面可见值做人工对照，确认指标身份、累计/增量口径、日期范围和作品归属。
6. 实机报告只持久化枚举结果、路径哈希、形状签名、数量、阶段和固定错误码，不保存任何业务值。

未达到全部门槛的端点只能留在验证器白名单候选中，不得接入生产转换器。

## 6. 系统架构

可交互架构图：[`docs/architecture/xiaohongshu-data-monitoring.html`](../../architecture/xiaohongshu-data-monitoring.html)

```text
数据监测页
  → 根据 accountId 读取 platformType
  → collector_for_platform(platformType)
      ├─ 3: DouyinDataCollector
      └─ 1: XiaohongshuDataCollector
            → 独立短会话
            → 官方响应合同匹配
            → 白名单字段转换
            → CollectionBatch
  → platform_data_service.record_collection_sync()
  → 本地趋势 / 作品列表 / 作品详情查询
```

### 6.1 采集器注册

`collector_for_platform()` 改为显式注册表，仅注册已有生产适配器的平台类型。未注册类型继续固定返回 `collector_not_available`，不做默认平台推测。

实施时先把当前只声明 `collect()`、但真实编排却调用 `collect_direct()` / `collect_browser_signed()` 的协议偏差收束为可执行合同。统一协议显式声明两个入口，并使用平台中性的 `PlatformDataCollectionError(error_code, fallback_allowed)`：

- `collect_direct(account) -> CollectionBatch`
- `collect_browser_signed(account) -> CollectionBatch`

抖音现有异常与行为通过兼容层保留。小红书当前没有已证明的直连合同，因此 `collect_direct()` 不发网络请求，只返回可回退的固定失败；`collect_browser_signed()` 执行短会话被动观察。两个平台最终都向编排层返回标准 `CollectionBatch`，编排层不再只捕获抖音专用异常。

### 6.2 会话边界

- 每次同步创建新的 context/page，不与发布、登录、上一次同步共用运行时状态。
- 只使用账号管理已有的本地会话文件，不导出 Cookie。
- 导航主机和所有接受的响应主机都必须通过白名单。
- 单页、整次采集、响应体大小、作品数和分页数均设硬上限。
- 成功、失败、取消、验证、登录失效和进程控制异常都进入同一严格 cleanup。
- cleanup 必须继续尝试关闭 page/context/browser/playwright，最终仅在 `closed=True` 且严格内建整数存活数为 0 时完成同步。

### 6.3 合同解析

每类官方响应使用独立 parser，只接受精确外形：

- 顶层节点类型必须正确。
- 所有 ID 必须是非空字符串，数值必须是内建 `int` / `float` 且非布尔值。
- 不接受宽松 `int()` / `str()` 转换。
- 不认识的字段只能忽略，不能透传到模型、数据库或 UI。
- 同一指标同一口径重复或冲突时整个响应固定失败，不“选一个看起来合理的值”。

### 6.4 指标与可用性语义

只有真实合同中已证明身份和口径的字段，才能映射到现有公开指标：

- 账号日增量：`views`、`likes`、`comments`、`shares`、`followers_net`、`profile_visits`。
- 账号累计量：仅 `followers_total`。
- 作品累计量：`views`、`likes`、`comments`、`shares`、`favorites`、`downloads`。

这个列表是应用公开模型的能力上限，不是小红书必然提供的字段清单。某个小红书合同未提供对应字段时，必须保持“不可用”，不生成 0 值 `MetricPoint`。

当账号指标可用但作品数据未取得时，使用现有 `partial_success` 和 `content_list_unavailable` / `content_payload_invalid`。作品取得但分页未证明穷尽时，使用 `content_list_truncated`，同时明示“最近 N 条”，不声称全部作品。

### 6.5 错误和进度

优先复用现有公开错误码：

- `session_state_missing`
- `login_required`
- `direct_request_rejected`
- `browser_signature_timeout`
- `browser_cleanup_incomplete`
- `metric_payload_invalid`
- `metric_payload_empty`
- `account_trends_unavailable`
- `content_list_unavailable`
- `content_list_truncated`
- `content_payload_invalid`

如真实合同阶段证明需要新错误语义，必须先增加固定码、UI 文案和持久化白名单测试，不可将平台异常原文带到 UI 或数据库。

同步进度文案改为平台中性语义，例如“正在读取官方签名数据”，不再固定显示“抖音官方签名数据”。

## 7. UI 设计

### 7.1 账号切换

- “平台”下拉框只加载“平台类型已注册数据采集器”的平台；首期为抖音和小红书。
- “主体”下拉框只显示当前平台下的活动账号，文案为 `主体名｜账号名`，内部保存严格账号 ID。
- 每个平台独立记住本次客户端会话最后选中的主体；切回该平台时优先恢复，不跨平台复用 accountId。
- 切换平台或主体时，先清空上一主体的卡片、趋势和作品表，再按新 accountId 重读本地数据。
- 当前平台没有账号时，主体下拉框为空，同步按钮禁用，并提示先去账号管理登录该平台。

### 7.2 数据展示

- 卡片标题表达语义而不表达某平台特有名词。
- 卡片附带口径：“账号趋势·近 7 天”或“作品累计值·平台观测时间”。
- 无可信值时显示——，并显示“平台未提供”、“本次未取得”或固定错误文案。
- 作品列表每行明确标注发布时间、作品类型、可用指标和本次覆盖范围。
- 数据页只显示数据库中已完成原子写入的快照，同步中的临时值不直接投影到卡片。

## 8. 持久化与隐私

- 复用现有同步运行、指标快照、作品和指标来源表，不为小红书创建平行数据库。
- 一次 `CollectionBatch` 与同步运行状态在同一事务中落库；任一阶段失败不留部分快照。
- 只保存公开模型白名单字段、固定错误码、来源模式和观测时间。
- 封面 URL 必须通过小红书官方静态资源域白名单，并删除 query/fragment；白名单在真实证据出现后才增加。
- 不保存请求 header/body、完整原始 URL、Cookie、验证码、二维码或平台 HTML。

## 9. 实施阶段

### 阶段 A：真实合同补全

- 扩展现有验证器的安全路由，覆盖数据概览、作品列表和单作品详情。
- 只产出脱敏形状报告。
- 由用户对实机页面和报告完成一次人工对照。

### 阶段 B：采集器和转换器

- 实现独立小红书会话、白名单 matcher/parser 和严格 cleanup。
- 实现 `XiaohongshuDataCollector`并注册平台类型 1。
- 用全部本地 fake response 完成字段转换、大小/分页上限、异常和关闭测试。

### 阶段 C：多平台 UI 和本地查询

- 账号下拉框改为平台感知显示。
- 同步、概览、趋势、作品列表、作品详情全部以所选账号 ID 为边界。
- 切换、快速连点、同步失败、页面关闭和迟到回调都验证账号/任务身份。

### 阶段 D：一次实机只读验收

- 必须由用户对本次实机运行单独明确授权。
- 只同步已确认的小红书账号，不读其他账号。
- 人工核对账号概览、作品数量、一条作品详情和时间口径。
- 回读同步运行、数据库快照、UI 展示和资源关闭状态。

## 10. 测试策略

1. **合同 parser 单测：** 正常外形、缺键、错误类型、重复 ID、冲突值、过大载荷、非白名单域。
2. **采集器单测：** 概览、列表、详情三类响应任意顺序，重复响应，部分可用，分页截断，登录失效，验证页，超时。
3. **资源测试：** 每个成功和失败路径都断言 context/browser/playwright 关闭，关闭失败不记成功。
4. **持久化测试：** 事务中任一写入点故障全量回滚，不同平台/账号快照完全隔离。
5. **UI 测试：** 抖音/小红书切换，——语义，中途切换，双击去重，迟到回调拒绝，未注册平台禁用。
6. **静态安全门：** 禁止请求重放、Cookie 输出、响应值持久化、DOM 爬取和平台写操作。
7. **最终回归：** 先跑新增目标测试，再跑平台数据受影响模块，最后只跑一次全量。

## 11. 验收标准

### 交付闭环

- 数据监测下拉框可显示并切换抖音与小红书账号。
- 小红书选项调用独立 collector，所有本地单测、受影响模块和最终全量测试通过。
- 代码扫描证明无 Cookie/签名输出、无请求重放、无平台写操作。

### 运行闭环

- 一次明确授权的实机同步取得至少一个已验证的账号指标合同。
- 如作品合同可用，同步至少一页作品并回读一条作品详情；如不可用，必须以 `partial_success` 明示，不写虚假作品数据。
- 数据库与 UI 数值同官方页面人工核对一致，缺失值为——而非 0。
- 会话结束后严格回读存活资源为 0。

### 结果闭环

本设计不声称已达成结果闭环。结果闭环需要后续连续同步产生可用趋势，并证明数据确实支持内容复盘或运营决策。

## 12. 失败策略、回滚与风险

- 合同不完整：不注册小红书生产 collector，页面不冒充可同步。
- 登录失效/验证：固定停止并引导账号管理，不自动输入凭据。
- 平台合同变化：parser fail closed，旧快照仍可查看，本次不覆盖。
- 作品数据不完整：账号指标可原子保存为 `partial_success`，作品部分不写入不完整数据。
- 会话关闭不完整：同步运行固定失败，不自动启动新会话。
- 需要回滚时，可从 collector 注册表移除平台类型 1，UI 自动不再提供同步；历史快照保留，不做数据删除。

最大残余风险是小红书后台合同、动态签名和风控可随时变化。因此生产适配器必须把“数据未取得”视为合法、可观测的结果，而不是使用宽松解析或虚构 0 值保持界面好看。
