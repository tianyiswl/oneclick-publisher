# 国内四平台数据监测设计

## 目标

在现有抖音、小红书数据监测基础上，依次接入公众号、视频号、B站和快手。用户在数据监测页选择“平台 → 主体 → 时间区间”后，可以用已有登录态读取官方创作者后台数据，并在本地查看账号趋势和作品表现。

本阶段完成标准不是“平台注册表里出现了名字”，而是每个平台均满足：

1. 真实账号同步成功；
2. 同一登录态连续第二次同步仍成功；
3. 同步批次、指标和作品均写入 SQLite 并可读回；
4. 页面能区分真实零值、平台未提供和暂未取得；
5. 登录失效、平台验证、接口变化和资源清理失败均有明确且脱敏的错误；
6. 单个平台失败不影响其他平台已有数据。

## 范围与顺序

国内平台按以下顺序实施：

1. 公众号：当前账号库只有演示账号，先完成适配器和离线合同；真实账号登录后完成运行验收。
2. 视频号：复用腾讯系登录会话管理，但数据接口和公众号保持独立。
3. B站：使用创作中心登录态，只读取账号和稿件数据。
4. 快手：使用创作者服务平台登录态，只读取账号和作品数据。

TikTok、YouTube、Instagram 和 Facebook 不进入本设计的实现范围，留到国内四个平台完成后单独设计和验收。

## 架构

采用“统一同步骨架＋平台独立适配器”，架构图见：

- `docs/architecture/multiplatform-data-monitoring.html`
- `docs/architecture/multiplatform-data-monitoring.json`

现有 `platform_data_sync.py` 继续负责同步编排，`platform_data_collectors.py` 负责按 `platformType` 选择采集器，`platform_data_service.py` 负责原子写入和查询。每个平台新增独立采集器与独立字段合同，不共享未经证实的 URL、选择器或响应结构。

平台适配器只输出统一的 `CollectionBatch`：账号指标使用 `entityType=account`，作品指标使用 `entityType=content`。平台原始字段名保存在 `rawMetricKey`，统一字段名写入 `metricKey`，避免不同平台同名指标被误认为相同口径。

## 数据口径

所有平台优先支持以下公共字段；平台未提供时写为不可得，不补成 `0`：

- 账号：粉丝总数、净增粉、主页访问；
- 作品：标题、发布时间、内容类型、播放或观看、点赞、评论、分享、收藏；
- 追溯：平台观察时间、本地同步时间、来源模式、原始指标名、统计周期和累计/区间口径。

平台独有指标允许进入统一表，但必须使用明确的 `metricKey` 和 `rawMetricKey`，页面未设计展示前不强行塞入公共卡片。

## 采集与安全边界

采集器使用账号管理保存的本地登录态打开官方创作者中心，只监听当前页面自然产生的官方 HTTPS JSON 响应，不主动调用未经审核的隐藏接口，不读取或输出 Cookie、请求头、响应正文、HTML、验证码和异常原文。

每次同步使用短会话：启动、采集、解析、关闭。请求数、目标响应数、单响应大小、累计响应大小和总耗时均有上限。页面图片、脚本和非白名单接口不占目标响应预算。

不再要求同一个页面同时显示账号卡片、作品列表和作品详情。官方响应通过域名、路径、阶段、字段类型和作品 ID 校验后即可形成候选批次；数据库事务写入后必须读回本批次的行数和关键指标，失败则整批撤销。

## 失败处理

失败统一归为用户能理解的几类：

- 需要重新登录；
- 需要完成平台验证；
- 平台页面或数据接口已变化；
- 平台暂未返回账号数据或作品数据；
- 本地写入或读回失败；
- 浏览器会话未完整关闭。

诊断只保存固定的平台、阶段和原因枚举，不保存敏感正文。失败运行写入同步记录，但不写入半批指标或作品，也不覆盖最后一次成功数据。

## 页面行为

数据监测页继续使用两个下拉框选择平台和主体。只有已注册采集器且账号库存在该平台账号时，平台才出现在下拉框中。同步期间按钮禁用，完成后恢复；切换平台或主体不会让上一任务的迟到结果覆盖当前页面。

账号和作品卡片显示当前选择区间的数据。累计值、区间增量和平台未提供必须使用不同文案。当天首次采集只证明当前累计值；需要跨日差值的卡片在没有两个不同日期快照前显示“暂未取得”。

## 测试与真实验收

每个平台按同一阶梯推进：

1. 用脱敏响应形状建立解析器红绿测试；
2. 测采集阶段绑定、超时、大小限制、清理和错误脱敏；
3. 测注册表、同步编排、原子写入和页面选择；
4. 运行该平台受影响模块测试；
5. 使用真实账号执行一次同步并核对页面与数据库；
6. 立即执行第二次同步，确认会话和资源状态可重复使用；
7. 四个平台完成后运行全量测试。

没有真实账号登录态时，只能标记为“代码与离线合同完成，等待真实验收”，不能称平台数据监测已完成。

## 不做的内容

- 不使用官方开放 API 资格作为前置条件；
- 不通过复制 Cookie 到第三方工具获取数据；
- 不抓取消费者端公开主页代替创作者后台口径；
- 不自动发布、修改或删除平台内容；
- 不为尚未观察到的字段猜测接口或伪造数据。
