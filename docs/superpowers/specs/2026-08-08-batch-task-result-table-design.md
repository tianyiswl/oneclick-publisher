# 批量任务结果表格设计

## 背景与问题

任务 `T08082217-665B` 共执行 19 条抖音带货视频，其中 18 条成功、1 条失败。失败项实际为第 12 条 `测试13.mp4`，但现有任务明细把 19 条视频、地点和排期拼成一段 `commerceSummary`，放进顶部摘要面板。长文本把真正的“执行项”表格推到窗口下方，用户无法第一眼定位失败视频，也难以逐条核对成功、失败、地点和定时时间。

数据库已经在 `publish_task_items` 中逐条保存 `batchItemIndex`、`fileName`、`locationSummary`、`scheduleSummary`、`status`、`message`、`attempts`、`startedAt` 和 `finishedAt`。本次不改任务数据模型，只调整原生任务明细窗口的展示方式。

## 目标

1. 打开抖音带货批量任务明细时，首屏直接看到逐视频结果表。
2. 每一条视频明确显示序号、文件名、地点、定时时间、状态和结果说明。
3. 失败项使用清晰但不过度刺眼的红色强调，并自动定位到第一条失败记录。
4. 支持按全部、成功、失败、执行中和未开始筛选。
5. 成功、失败和未开始的完整信息都来自本地任务回执，不推断平台状态。
6. 普通非批量任务继续使用现有明细布局，不受本次改动影响。

## 方案选择

采用“批量任务专用结果表格”方案。

不采用只扩大现有通用执行项表格的方案，因为通用表格包含平台、账号主体、账号名和备注等批量内重复字段，地点和排期反而不可见。不采用折叠长摘要方案，因为用户仍需额外展开并在文本中查找失败项。专用表格直接使用逐条任务记录，信息密度和错误定位最清楚。

## 信息架构

### 顶部摘要

批量任务顶部只保留：

- 任务号；
- 任务类型与任务场景；
- 总体状态；
- 标题；
- 账号与平台；
- 创建时间与完成时间；
- 批量结果：总数、成功、失败、未完成；
- 总体失败原因，仅在任务存在 `lastError` 时显示。

批量任务不再在顶部展示完整 `commerceSummary`。普通任务仍保留现有“带货信息”摘要。

### 批量结果页签

批量任务的第一个页签命名为“视频结果（N）”，内容由状态筛选栏和表格组成。表格固定为以下六列：

| 列 | 内容 | 展示规则 |
| --- | --- | --- |
| 序号 | `batchItemIndex` | 固定窄列，缺失时回退到当前行序号 |
| 视频 | `fileName` | 只显示文件名，完整路径放入悬停提示 |
| 地点 | `locationSummary` | 显示名称与完整地址，悬停可查看全文 |
| 定时时间 | `scheduleSummary` | 保留“北京时间定时”口径 |
| 状态 | `status` 的中文标签 | 成功绿色、失败红色、执行中蓝色、未开始灰色 |
| 结果说明 | 根据状态生成的简短结果 | 成功显示“平台已回读”；失败显示完整失败原因；未开始显示“尚未开始”；完整原始消息保留在悬停提示 |

表格保持 `batchItemIndex` 顺序，不默认按状态重排，避免打乱排期。首次打开时，如果存在失败项，选中并滚动到第一条失败记录。失败行使用浅红背景，状态和说明使用深红文字；成功行不铺绿色背景，只将状态显示为绿色，减少视觉噪声。

### 状态筛选

筛选项为：

- 全部；
- 成功；
- 失败；
- 执行中；
- 未开始。

每个筛选项显示当前数量。切换筛选只改变本地表格内容，不修改任务数据，也不触发重新读取平台。

### 其他页签

“事件日志”和“发布参数”继续保留。非批量任务的第一个页签继续使用原有通用“执行项”表格。

## 组件边界

`TaskDetailDialog` 负责判断当前任务是否为 `douyin-commerce-batch`：

- 批量任务调用新的批量结果组件；
- 其他任务调用原有 `_items_tab()`；
- 两种路径共用事件日志和发布参数页签。

批量结果组件只消费 `task_service.get_task()` 已返回的 `items` 字段，不直接访问数据库。数据查询、任务状态计算和平台回执写入逻辑保持不变。

## 数据流

1. 用户在任务记录页打开明细。
2. `task_service.get_task(task_id)` 返回任务、逐条执行项和事件。
3. 明细窗口识别 `workflow == "douyin-commerce-batch"`。
4. 顶部生成紧凑摘要，不渲染长 `commerceSummary`。
5. 批量结果组件按 `batchItemIndex` 排序并计算各状态数量。
6. 筛选器在内存中筛选行，重新渲染同一张表格。
7. 表格选中并滚动到当前筛选结果中的第一条失败项。

## 状态与错误处理

- `success`：显示“成功”，结果为“平台已回读”。
- `failed`：显示“失败”，结果使用任务项 `message`；空消息时显示“未记录具体失败原因”。
- `running`：显示“执行中”，结果优先使用 `message`，否则显示“正在执行”。
- `pending`：显示“未开始”，结果显示“尚未开始”。
- 其他未知状态：保留原始状态和值，不把未知状态猜成成功或失败。
- 地点、时间或文件名缺失时显示“—”，不让表格错位或报错。
- 表格只是本地记录的展示层，不改变历史任务状态，不提供重试或重新发布按钮。

## 测试设计

新增原生界面回归，使用离屏 Qt 构造批量任务明细：

1. 顶部不再出现长“带货信息”，但显示批量结果统计。
2. 第一个页签为“视频结果（N）”。
3. 六列表头、逐条视频、地点、排期和中文状态正确。
4. 成功行结果简化为“平台已回读”，原始消息仍在悬停提示中。
5. 失败行显示完整原因并使用失败色，首次打开自动选中第一条失败项。
6. 状态筛选切到“失败”后只显示失败视频。
7. 非批量任务仍显示原有十列“执行项”表格。

## 设计自审

- 规格没有待定字段；列、状态、筛选和缺失值行为均已明确。
- 顶部摘要与逐条结果职责分离，不再重复展示 19 条长文本。
- 表格保持原发布顺序，同时用失败高亮和自动定位解决查找问题。
- 展示完全依赖现有本地回执，不把上传、编辑页填写或本地状态误写成平台成功。
- 改动限定在任务明细展示层，不扩大到发布和重试流程。
