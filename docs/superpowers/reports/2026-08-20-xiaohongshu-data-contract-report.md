## 2026-08-21 首次真实运行结果

经大帅本次明确授权，正式页面对“小红书 → 硅基探索”（账号 ID `18`）只点击了一次
“同步数据”。运行打开了 headed 官方只读会话，但最终固定失败为
`metric_payload_invalid`，本地没有写入新的指标或作品快照，也没有重试。

失败发生在响应刚返回的同一秒。对照仓内此前已经真实成功的合同探测器后确认：四个审核过的
官方 JSON 接口均允许分块传输、可能缺少 `Content-Length`；压缩响应的声明长度也不等于
Playwright `response.body()` 返回的解压后长度。新采集器遗漏了这条既有合同，错误地要求长度头
必须存在且与解压正文完全相等，因而在解析 JSON 前拒绝了正常响应。

已用 TDD 修复为：四个白名单接口允许无长度头；存在的合法长度仍用于读取前的 1 MiB/4 MiB
预算预检；读取后继续按实际正文长度执行单体与累计上限，不再要求压缩长度完全相等。新增回归
先稳定复现旧实现失败，修复后采集器模块 `37/37` 通过，`py_compile` 与 `git diff --check` 通过。
该修复随后获得第二次真实运行授权；结果见下一节，仍不能写成真实同步成功。
