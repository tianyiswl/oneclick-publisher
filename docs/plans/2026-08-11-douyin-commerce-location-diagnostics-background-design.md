# 抖音带货地点恢复、任务日志与前后台运行设计

## 目标与边界

本次修复解决三条互相关联的数据链。第一，平台设置阶段选择地点时，不再只保存 POI、名称、地址和范围，还要把产生该候选的原始搜索词绑定到每条视频。正式发布页重新搜索时优先复用原始搜索词，并以品牌短词、完整店名和地址作为有界兜底；最终仍以官方 POI ID 或规范化名称与地址唯一匹配，不能因为提高召回率而降低防误选标准。第二，执行日志要记录视频序号、视频名、地点范围、保存地点、实际尝试的关键词、每次候选数量及最终固定错误码，使 `publish_location_candidate_missing` 能直接定位到“搜索未返回、返回候选不匹配或点击回读失败”。第三，检查与提交页增加“后台运行”勾选框，默认勾选。取消后，正式发布为每条视频创建可见的受控 Chromium；勾选时继续使用真正无头浏览器。两种模式共用完全相同的上传、设置、验证和平台回执判定。

## 数据流与兼容策略

地点原始搜索词作为 `locationPreset.searchKeyword` 随当前批次和本地草稿保存，批次校验后投影成单条运行载荷的 `locationSearchKeyword`。旧草稿和旧任务没有该字段时，从店名提取首个有效英文/数字品牌片段，再回退现有地址、城市加店名和完整店名策略，因此不要求迁移数据库。每次地点恢复由批量执行器先写一条任务级摘要，页面适配层再逐关键词记录搜索结果和不匹配原因，最终弹窗把固定错误码翻译为中文，但仍保留错误码方便检索。

执行日志只清理共享的客户端日志总线，不删除任务事件或数据库记录。一个批次产生最终汇总后设置“下一新任务清理”标记；用户查看完结果、返回内容准备并再次进入平台设置时才清空旧日志并写入新任务起始行。原批次失败后直接重试不会被误判为新任务，诊断日志仍保留。

## 验收标准

- 使用 `JOYMARK` 搜索并选择英文、中英文混排店名后，正式发布首先尝试 `JOYMARK`。
- 旧任务没有原始关键词时，能够从 `JOYMARK(株洲王府星mall店)` 提取 `JOYMARK` 兜底。
- 地点恢复失败日志能显示视频、范围、目标地点、关键词、候选数量和具体失败阶段。
- 批次结束后日志仍可查看；开始下一批平台设置时才自动清空。
- “后台运行”默认勾选；取消后正式发布浏览器可见，勾选后保持无头。
- 地点唯一匹配、验证码处理和最终平台回执安全边界不变。
