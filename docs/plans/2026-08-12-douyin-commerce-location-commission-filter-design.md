# 抖音带货地点返佣筛选设计

## 背景

抖音带货地点搜索结果会同时出现返佣地址和无佣地址。当前一键发虽然能从官方候选行读到类似“15件商品 · 15件返佣”的公开摘要，但归一化地点时只保留名称、完整地址和可见 POI 身份，返佣信息随后被丢弃。因此，平台设置无法按返佣状态过滤，正式发布恢复地点时也无法复核设置阶段的返佣要求。

本次优化只增加候选筛选和正式发布复核，不改变现有“国内／本地”搜索、同面板唯一精确匹配、已选地点不被后续搜索覆盖等安全规则。

## 已确认的产品规则

### 设置页布局

批量地点搜索栏调整为：

`返佣筛选〔返佣▼〕  地点范围〔国内▼〕  关键词  搜索地点`

返佣筛选固定提供三项：

- `全部`
- `返佣`
- `无佣`

新建批次、整批完成后开始下一批以及放弃后重新开始时，默认选择 `返佣`。已有任务或草稿如果已保存筛选状态，则恢复其原状态。

### 分类口径

- 候选明确显示返佣数量且数量大于 0：归为 `返佣`。
- 候选没有商品／返佣标识：按平台当前可见规则归为 `无佣`。
- 候选明确显示返佣数量为 0：归为 `无佣`。
- 候选含“返佣”等关键词，但数量或含义无法稳定解析：归为 `unknown`，只在 `全部` 中展示，不能误归为返佣或无佣。

### 自动填入

- 平台先返回原始完整候选，一键发再按当前返佣筛选过滤。
- 只给当前显示“请选择地点”的视频自动填入。
- 已经选好的地点保持不变；用户主动选回“请选择地点”后，该视频才重新参与下一次自动填入。
- 筛选后的候选不足时，按候选顺序填入可用数量，其余视频继续显示“请选择地点”。
- 筛选结果为空时不回退到全部、不默认选第一项，也不做模糊匹配。

## 候选数据模型

地点候选继续使用名称、完整地址和 POI 身份作为地点身份，并新增以下公开结构化字段：

```text
commissionType: commission | no_commission | unknown
productCount: int | null
commissionProductCount: int | null
commissionLabel: 返佣 | 无佣 | 待确认
```

候选提取只读取当前可见结果项中的公开摘要，不保存原始 DOM、HTML、Cookie、账号路径或异常原文。`commerceInfo` 只在当前解析回合使用，离开提取层后仅传递上述结构化字段。

返佣状态不是地点的永久身份。账号级地点预设仍只长期保存 POI、名称、地址、搜索范围和验证时间，不能因为一次搜索看到返佣就把该地点永久标记为返佣。

每条视频的本批次地点快照新增：

```text
commissionFilter: all | commission | no_commission
observedCommissionType: commission | no_commission | unknown
productCount: int | null
commissionProductCount: int | null
```

其中 `commissionFilter` 表示用户选择该地点时的发布要求；`observedCommissionType` 和数量只用于任务明细展示与诊断。后续切换顶部筛选不会改写已经保存到视频上的筛选要求。

## 候选提取与过滤顺序

1. 在同一打开的官方地点面板内逐项读取名称、完整地址和返佣摘要。
2. 解析返佣摘要，生成结构化返佣字段。
3. 先按 `commissionFilter` 过滤候选。
4. 再对过滤后的候选按地点身份做唯一性检查和去重。
5. 返回过滤结果给设置页展示和自动填入。

必须先过滤、后做地点唯一性判断。若官方页面用相同名称和地址展示返佣与无佣两个可点击项，`返佣` 或 `无佣` 筛选可能把它收敛为唯一项；`全部` 下仍存在多个同身份结果时，应标记为歧义并停止自动选择。

## 设置页交互反馈

候选下拉项在名称和地址之外增加返佣标签：

- `返佣`：可同时显示“15件商品 · 15件返佣”。
- `无佣`：不伪造数量，只显示“无佣”。
- `待确认`：只会在“全部”筛选下出现。

搜索完成后状态栏同时显示平台返回数、筛选后数量、自动填入数和剩余待选数。例如：

```text
平台返回 18 个，返佣地址 12 个，自动填入 12 条；还有 8 条待选择。
```

筛选结果为空时显示：

```text
平台返回 18 个，但没有符合“返佣”条件的地址；未自动填入。
```

国内和本地搜索共用当前返佣筛选，但切换范围后仍必须重新取得当前输入框和最新候选，不能复用切换前的 DOM 或旧候选。

## 正式发布复核

正式发布继续使用每条视频独立的新会话，并在同一个打开的地点面板内完成搜索、筛选、唯一匹配、点击和回读：

1. 根据保存的搜索范围和有限关键词重新搜索。
2. 解析当前平台候选的返佣状态。
3. 按该视频保存的 `commissionFilter` 过滤当前候选。
4. 在过滤结果中按 POI、名称和规范化完整地址唯一匹配保存地点。
5. 唯一匹配成功后点击，并回读最终选中的地点身份。

若地点仍存在但当前返佣状态不再满足保存要求，当前视频以固定原因 `publish_location_commission_mismatch` 失败，任务明细显示：

```text
地点存在，但当前返佣状态与设置时不一致。
```

该失败只影响当前视频，批处理继续下一条；不得自动换成其他地点、不得回退到全部地址。筛选为 `all` 时只复核地点身份，不限制返佣状态。

旧任务缺少 `commissionFilter` 时按 `all` 兼容，避免历史任务因新增字段无法恢复。新建任务必须保存有效的返佣筛选值。

## 状态生命周期

- 新建批次：返佣筛选为 `返佣`。
- 放弃本次上传并重新开始：清空候选和每条视频的平台设置，返佣筛选恢复 `返佣`。
- 整批明确完成后开始下一批：返佣筛选恢复 `返佣`。
- 当前批次切换“全部／返佣／无佣”：只改变下一次搜索及新填入结果，不覆盖已选视频。
- 当前批次切换“本地／国内”：保留返佣筛选，重新搜索当前范围。
- 关闭候选面板、取消采集或退出客户端：沿用现有代际关闭和零存活屏障，不新增后台长期会话。

## 错误边界

- 返佣摘要无法解析：候选为 `unknown`，仅进入“全部”。
- 筛选结果为空：不填入，显示固定说明。
- 过滤后仍有重复地点身份：标记歧义，不自动填入。
- 正式发布返佣状态变化：`publish_location_commission_mismatch`，只失败当前视频。
- 正式发布无法读取返佣状态且任务要求返佣或无佣：按状态不一致安全停止当前视频。
- 日志和任务明细只记录筛选类型、候选数量、地点公开名称／地址和固定错误码，不记录原始 DOM 或异常敏感文本。

## 方案取舍

采用端到端结构化方案，而不是只在设置页临时隐藏列表项：

- 设置页过滤与正式发布使用同一分类函数，口径一致。
- 每条视频保存筛选意图，后续切换全局筛选不会污染已选地点。
- 正式发布会重新核对实时返佣状态，避免设置页选择正确而发布时点击到另一类候选。

不采用 UI 文字临时过滤或默认第一项方案，因为它们无法跨页面重绘和独立发布会话保持可靠身份。

## 验证计划

按“发现失败即停止、修复后只重跑对应专项、收尾只跑一次完整回归”的节奏执行：

1. 返佣解析专项：覆盖“15件商品 · 15件返佣”、0 件返佣、无标识、仅商品标识、异常返佣文字。
2. 候选归一化专项：验证只保留公开结构化字段，unknown 不误分类。
3. 设置页专项：验证默认返佣、三种筛选、状态文案、候选标签和筛选为空。
4. 自动填入专项：验证只填空行、已选不覆盖、清回“请选择地点”后可重新填入、候选不足不回退。
5. 状态生命周期专项：验证新批次和放弃重置为返佣，已有任务恢复自己的筛选意图。
6. 任务载荷专项：验证每条视频保存独立 `commissionFilter`，旧任务缺字段按全部兼容。
7. 正式发布专项：验证先筛选后唯一匹配、返佣状态变化只失败当前视频、后续视频继续。
8. 全部专项通过后，只运行一次完整回归、`py_compile` 和 `git diff --check`。
9. 自动测试不访问抖音、不上传、不预检、不保存草稿、不正式发布。代码收尾后再由用户使用真实账号分别验证“返佣／无佣／全部”。

## 验收标准

- 设置页显示“全部／返佣／无佣”，新批次默认“返佣”。
- 三种筛选得到符合口径的候选，自动填入只影响未选视频。
- 任务明细能看出每条视频选择的是返佣还是无佣。
- 正式发布不会把返佣要求降级为无佣地址，也不会在无结果时回退。
- 返佣状态变化时原因明确、仅当前视频失败、后续视频继续。
- 旧任务仍可按原有地点身份发布，且不被错误标记为返佣。
