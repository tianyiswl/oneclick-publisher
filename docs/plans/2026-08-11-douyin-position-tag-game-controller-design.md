# 抖音位置标签误选游戏手柄修复设计

## 问题

选择收藏音乐后，抖音会重绘“添加标签”区域。旧适配在找不到明确入口时会点击整块右侧容器，并把“位置”菜单项先标记、再通过异步 Locator 点击。React 重绘期间标签类型节点可能被复用，导致最终点击时节点已经变成“游戏手柄”。

## 方案

1. 在“添加标签”对应的唯一 `new-layout` 行内识别非筛选型标签类型下拉，不依赖当前文案必须已经是“位置”。因此当前值即使是“游戏手柄”，客户端也能重新打开类型菜单。
2. “位置”选项的唯一性校验与点击在同一个浏览器 JavaScript 执行回合完成，消除标记节点与后续点击之间的重绘窗口。
3. 只接受可见、文字完全等于“位置”的唯一菜单项；只有“游戏手柄”或出现多个“位置”时安全停止。
4. 点击后仍由现有完整控件组回读确认“位置 + 带货模式 + 地点输入框”，不降低发布安全边界。

## 验收

- 当前标签为“游戏手柄”时能识别并重新打开标签类型下拉。
- 菜单同时有“游戏手柄”和“位置”时只选择“位置”。
- 菜单没有唯一“位置”时不点击任何选项。
- 音乐、声明、地点和批量发布现有回归全部通过。
