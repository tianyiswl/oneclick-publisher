# 海外平台源码与能力对照

## 来源结论

本轮只读核对了恢复的蚁小二海外适配器：

`/Users/andy/Documents/AI/codex/Projects/代码迁移优化/蚁小二完整代码恢复/reconstructed-app/packages/main/local-overseas/index.cjs`

TikTok、YouTube、Instagram 和 Facebook 四个平台都能在该恢复源码中找到，因此没有从未经审计的第三方 Git 项目复制发布逻辑。恢复源码的能力边界是：

- 只有视频通道；
- 通过 TikTok Studio、YouTube Studio 和 Meta Business Suite 填入视频与文案；
- 封面、定时、受众、AI 声明等平台字段有一部分依赖人工确认；
- 恢复适配器本身不点击最终发布。

一键发已将这些步骤改写为自有 Python/Playwright 适配器，不需要启动或依赖蚁小二客户端。同时，一键发另有独立的官方 OAuth/API 通道。

| Facebook Reels | Meta 目标选择、视频、文案、停在 Share 前；可受控正式发布 | OAuth + Graph API 上传/发布/回读 | 公开状态、标题、描述 | 官方 Reels 端点尚无已验证 AI 自声明字段；AI 内容会安全阻断，不会遗漏声明发布 |

## 已修正的一致性问题

1. Instagram 的 `share_to_feed` 不再写死，由“同时分享到 Instagram 动态”选项控制。
2. YouTube 增加“内容面向儿童”和“通知订阅者”，官方 API 请求与界面保持一致。
3. YouTube 浏览器预检不再固定选择“非儿童内容”，会按界面选择并回读真实控件。
4. 浏览器通道的可见性、合集、AI、受众、通知与动态选项会进入恢复执行器，不再在中间层丢失。
5. YouTube 描述按 UTF-8 字节校验；Instagram/Facebook 合并文案超限时阻断，不再静默截断。

## 真实验收门槛

离线测试只能证明路由、字段透传、安全阻断和回执解析约定正确。每个平台仍需使用专用测试账号和测试视频，在一键发中逐项验收：

1. 账号身份回读与所选账号一致；
2. 视频、标题、文案、封面和平台专属字段一致；
3. 定时任务回读准确时区与时间；
4. 收件箱、媒体容器、定时和公开发布的状态不混淆；
5. 登录失效、验证码、二次验证、风控和未知合规提示必须停止并让用户处理。
